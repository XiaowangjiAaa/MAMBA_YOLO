# 9.11 正式消融结果整理与成对特征可视化

## 1. 数据口径

本文件只把能够形成当前论文证据链的实验纳入主表：9.3 的 H 系列为模块机制与 YOLO-family 成对实验，9.1 的 G 系列为部署位置实验。所有数值均读取各 run 的 `segmentation_eval_report_best_map50.txt`，即重新加载 `best_map50.pt` 后在 200 张验证图像上的结果，不使用 `results.csv` 中未保存的瞬时峰值。

实际目录名称和 `args.yaml` 显示，这批 H/G 实验均为 `seed=0`，不是旧计划文档中写的 seed=1。因此当前表格属于 **controlled single-seed ablation**，尚不能报告 mean±std 或宣称跨随机种子稳定性。主指标按照项目约定为 Mask mAP50；Mask mAP50-95、AP75、Recall、mIoU 和 clDice 用于解释主指标变化。

## 2. 完整方法、原生基线与辅助监督控制

| ID | 结构辅助监督 | 路径/状态写回 | Mask mAP50 | Δ vs H00 | Mask mAP50-95 | AP75 | Recall | mIoU | clDice | Params | GFLOPs |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| H00 原生 YOLO11n-Seg | — | — | 0.6749 | — | 0.2238 | 0.0861 | 0.6848 | 0.6454 | 0.8566 | 2.73M | 9.62G |
| H02 Aux-only | ✓ | ✗ | 0.6984 | +0.0235 | **0.2288** | **0.0909** | 0.6707 | 0.6456 | 0.8540 | 2.74M | 9.65G |
| H01 完整方法 | ✓ | ✓ | **0.7079** | **+0.0330** | 0.2269 | 0.0824 | **0.7068** | **0.6509** | **0.8604** | 2.75M | 9.67G |

H01 相对原生 YOLO11 的 Mask mAP50 提升 3.30 个百分点，参数只增加约 0.02M。H02 控制配置（CSP-compatible host shell + structure head/辅助监督，但不写回 path-state residual）已经提高 2.35 个百分点；由于它同时改变了 shell 和监督，不能把这 2.35 个百分点全部归因于 auxiliary loss，但可以确认“非路由控制分支”的贡献不可忽略。H01 相对 H02 再提升 0.95 个百分点，并将 Recall 提高 3.61 个百分点，证明路径构建、状态传播和残差写回并非只有辅助头的假象。不过严格指标中 H01 不高于 H02，因此正确表述应是：完整路径状态分支主要改善宽松实例召回和 Mask AP50，而不是所有 IoU 阈值都同步提高。

验证报告中的单次 FPS 不纳入正式效率比较，因为完全相同的 H00/H24 分别报告 511.1/574.7 FPS，说明该字段受验证进程和瞬时负载影响较大。统一效率应使用 `benchmark_yaml_model.py` 在相同设备、batch=1、640×640、相同精度和多轮预热设置下重新测量。

## 3. Scan × Memory 二因素消融

| ID | Token ordering | Memory management | Mask mAP50 | Mask mAP50-95 | AP75 | Recall | clDice |
|---|---|---|---:|---:|---:|---:|---:|
| H03 | 固定 H/V/对角直线路径 | Standard | 0.7030 | **0.2377** | **0.1175** | 0.6773 | **0.8634** |
| H04 | 自适应曲线路径 | Standard | 0.6734 | 0.2253 | 0.0870 | 0.6586 | 0.8571 |
| H05 | 固定 H/V/对角直线路径 | Full crack-aware | 0.7048 | 0.2276 | 0.0956 | **0.7349** | 0.8561 |
| H01 | 自适应曲线路径 | Full crack-aware | **0.7079** | 0.2269 | 0.0824 | 0.7068 | 0.8604 |

以 Mask mAP50 计算：

```text
adaptive scan effect under standard memory = H04 - H03 = -0.0296
adaptive scan effect under full memory     = H01 - H05 = +0.0031
full memory effect under fixed scan        = H05 - H03 = +0.0018
full memory effect under adaptive scan     = H01 - H04 = +0.0345
interaction                                = +0.0327
```

这是目前最关键的机制结果。Adaptive scan 不是一个可以脱离 memory 独立使用的增益模块；在 standard memory 下它明显下降。Crack-aware memory 在固定路径下增益很小，却在 adaptive 路径下带来 3.45 个百分点恢复/提升，交互项为正。因此论文故事应写成 **structure-conditioned ordering and memory form one coupled state-propagation mechanism**，不能拆成“有效 scan + 有效 memory”的简单相加。

同时必须保留反面证据：H03 的 Mask mAP50-95、AP75 和 clDice 最高。完整方法当前偏向 Mask mAP50/Recall，严格边界定位仍有优化空间。

## 4. 自适应路径结构线索消融

| ID | 路径评分线索 | Mask mAP50 | Mask mAP50-95 | AP75 | Recall | mIoU | clDice |
|---|---|---:|---:|---:|---:|---:|---:|
| H06 | probability `p` | 0.6969 | 0.2298 | 0.0922 | 0.6764 | 0.6443 | 0.8535 |
| H07 | `p + orientation` | 0.6980 | **0.2323** | 0.1020 | 0.6756 | **0.6482** | **0.8597** |
| H08 | `p + connectivity` | 0.6903 | 0.2316 | **0.1041** | 0.7028 | 0.6446 | 0.8561 |
| H01 | `p + orientation + connectivity` | **0.7079** | 0.2269 | 0.0824 | **0.7068** | 0.6509 | 0.8604 |

完整 `p+o+c` 在主指标上最高，相对只用 `p` 提高 1.10 个百分点，并提高 Recall 3.04 个百分点，支持方向与连通性联合参与路径构建。但 H07/H08 的严格 AP 更高，说明 `c` 与 `o` 的当前融合更像提升候选覆盖，而非提升高 IoU mask 精度。文章中可以声称三类线索对主指标存在互补，不能声称完整线索在所有指标上最优。

## 5. Memory management 内部消融

| ID | Retention Δ | Transition Δ | Write B | Mask mAP50 | Mask mAP50-95 | AP75 | Recall | clDice |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| H09 | ✓ | — | — | 0.6891 | 0.2283 | **0.0942** | 0.6466 | **0.8604** |
| H10 | ✓ | ✓ | — | 0.6944 | **0.2349** | 0.0835 | 0.6739 | 0.8598 |
| H11 | ✓ | — | ✓ | 0.6969 | 0.2268 | 0.0839 | 0.6867 | 0.8498 |
| H01 | ✓ | ✓ | ✓ | **0.7079** | 0.2269 | 0.0824 | **0.7068** | **0.8604** |

相对 H09，仅加入 transition 提高 Mask mAP50 0.53 个百分点，仅加入 write 提高 0.78 个百分点；两者同时加入的 H01 提高 1.88 个百分点。这支持三段式职责：probability retention 决定记忆长度，predecessor connectivity 阻止不可靠跨边传播，probability-conditioned B 控制当前 token 写入。H10 的 Mask mAP50-95 最高，提示后续若优化严格定位，应优先调整 write 强度，而不是删除 transition。

## 6. 模块放置位置消融

此表的参考 G00 已经在 backbone P3/P4 使用模块，不是原生 YOLO11；其作用是回答模块部署范围，而非证明完整方法相对原生网络有效。

| ID | 替换位置 | Block 数 | Mask mAP50 | Δ vs G00 | Mask mAP50-95 | Recall | clDice |
|---|---|---:|---:|---:|---:|---:|---:|
| G00 | Backbone P3/P4 | 2 | 0.6888 | — | **0.2282** | 0.6736 | 0.8600 |
| G01 | Backbone P2/P3/P4/P5 | 4 | **0.7079** | **+0.0191** | 0.2269 | **0.7068** | **0.8604** |
| G02 | P3/P4 + 全部 Neck | 6 | 0.6868 | -0.0020 | 0.2275 | 0.6590 | 0.8567 |
| G03 | 除 P2 外的 Backbone+Neck | 7 | 0.6975 | +0.0087 | 0.2248 | 0.6948 | 0.8557 |
| G04 | 全部 Backbone+Neck | 8 | 0.6866 | -0.0022 | 0.2238 | 0.6667 | 0.8540 |
| G05 | 全替换，stage-adaptive budget | 8 | 0.6760 | -0.0128 | 0.2210 | 0.6768 | 0.8485 |

结果支持 G01 的 **backbone-wide replacement**，不支持 neck-wide 或全网无差别替换。合理解释是 backbone 各阶段仍保留稳定空间邻接，适合构造裂缝路径；neck 已经历上采样、拼接与跨尺度融合，重复路径路由会破坏或冗余增强融合特征。模块接口可以兼容 C3k2，但性能有效范围目前应限定为 backbone，而不是“可稳定替换所有 C3k2”。

## 8. 推荐的特征可视化证据链

仅展示 H00 与 H01 的普通 feature heatmap 不足以证明动态 scan 沿裂缝传播，因为通道热度只是空间响应，不等于 crack probability。建议形成四组成对证据：

| 比较 | 控制变量 | 最适合回答的问题 |
|---|---|---|
| H00 vs H01 | 原生网络 vs 完整方法 | 完整方法是否把 backbone 空间能量更多集中到裂缝区域 |
| H02 vs H01 | 相同结构监督，是否写回 path/state residual | 提升是否来自真实状态传播，而非辅助监督 |
| H03 vs H04 | Standard memory 下 fixed vs adaptive scan | 为什么 adaptive scan 单独使用会产生背景漂移 |
| H05 vs H01 | Full memory 下 fixed vs adaptive scan | Memory 是否使 adaptive scan 的传播重新对齐裂缝 |

层选择建议：

- 主文展示 P3/P4，即 YAML layer 4 和 6。P3 保留细裂缝几何，P4开始形成连续结构语义，最适合说明 scan 与 memory。
- 补充材料展示 P2/P3/P4/P5，即 layer 2、4、6、8。P2检验浅层纹理误激活，P5检验过粗空间分辨率。
- H01 还必须同时展示内部 `p`、orientation、connectivity、dynamic path 和 token coverage。只有路径覆盖确实沿 GT 裂缝延伸，才能支持“crack-aligned scan”。

## 9. 新的成对可视化脚本

根目录新增 `compare_model_features.py`。它对两个模型使用完全相同的 letterbox 输入，并输出：

- baseline/proposed 的通道 RMS 空间热图；
- 独立归一化对比图，用于观察空间形态；
- 共享尺度对比图，用于避免两张图分别拉伸造成的视觉误导；
- proposed-minus-baseline 红/蓝差异图；
- 有 GT 时的 crack/background focus ratio 和变化量；
- H01 内部 probability、orientation、四类 connectivity 与动态 token path；
- `feature_focus_metrics.csv` 和 `comparison_manifest.json`。

Windows PowerShell，推荐先比较 H00 与 H01 的 P3/P4：

```powershell
python compare_model_features.py --baseline-yaml "ultralytics/cfg/models/11/9.3-experiments/H00-yolo11n-seg-baseline.yaml" --baseline-weights "output_dir/crack-seg-9.3/H00_crack-seg_seed0/weights/best_map50.pt" --proposed-yaml "ultralytics/cfg/models/11/9.3-experiments/H01-g01-full.yaml" --proposed-weights "output_dir/crack-seg-9.3/H01_crack-seg_seed0/weights/best_map50.pt" --source "crack-seg/data.yaml" --split val --layers "4,6" --imgsz 640 --device 0 --max-images 10 --output-dir "feature_comparison/H00_vs_H01"
```

只处理验证集中的某一张图：

```text
--image-index 25 --max-images 1
```

必须注意：两个独立训练模型的 feature channel 不具备严格的一一对应关系，因此脚本不做单通道直接相减，而比较通道聚合后的空间能量、GT focus ratio 和模块内部结构场。热图只能作为机制证据的一部分，必须与消融表和最终 instance segmentation 结果共同呈现。

## 10. 当前最稳妥的论文结论

1. 完整 G01/H01 在当前单 seed 实验中相对原生 YOLO11n-Seg 将 Mask mAP50 从 0.6749 提高到 0.7079。
2. Scan 与 memory 存在明显正交互；adaptive scan 单独无效，crack-aware memory 使其成为有效的联合传播机制。
3. Probability、orientation、connectivity 对主指标存在联合互补，但严格 mask 定位仍弱于部分简化变体。
4. Backbone P2-P5 是当前最佳部署范围；neck 全替换和全网替换没有获得支持。
5. 模块具备跨 YOLO CSP 外壳的工程兼容性，但当前性能优势最明确的是 YOLO11，跨 family 普适增益仍需进一步设计或多 seed 证据。
