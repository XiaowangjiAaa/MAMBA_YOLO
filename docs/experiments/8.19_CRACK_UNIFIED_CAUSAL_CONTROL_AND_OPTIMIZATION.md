# 8.19 Unified Crack-Aware VSS 因果控制与定向优化

## 1. 8.17 结果给出的结论

8.17 的三 seed 结果表明，完整 T00 相比原始模型提高了 Mask mAP50，但没有稳定提高 Mask mAP50-95；相比只使用 Directional Merge 的 N04，T00 的 Mask mAP50-95 和 mAP75 都下降。

三 seed 的 mask-best 均值如下：

| 方法 | Mask mAP50 | Mask mAP50-95 | Mask mAP75 | Mask fitness |
|---|---:|---:|---:|---:|
| N00 原始 Mamba-YOLO | 0.6993 | 0.2395 | 0.0935 | 0.2855 |
| N04 三处 Directional Merge | 0.7041 | 0.2461 | 0.1016 | 0.2919 |
| T00 8.17 Unified 方法 | 0.7102 | 0.2399 | 0.0845 | 0.2869 |

但 N04 与 T00 同时存在两项差异：N04 在 P5 也使用 Directional Merge，而 T00 恢复了原始 P5 Merge 并增加 Unified Block。因此不能把全部下降直接归因于 Unified Block。

门控检查还发现：P3 write gate 在 T00 三个 seed 中接近零，P4 scan gate 较稳定，而允许正负的 write gate 在 T03 中学成了负数。这既不稳定，也会反转“裂缝区域增强写入”的理论解释。

## 2. 8.19 原则

8.19 不提出新 Stem、Merge、Scan 路径或 Memory 分支，只回答两个问题：

1. 在完全相同的前端和 P5 设置下，Unified Scan/State Update 是否优于 Standard VSS？
2. 如果保留 Unified Block，理论一致的非负门控和轻微幅度正则能否缓解后期过度传播？

## 3. 三个实验

YAML 位于 `ultralytics/cfg/models/mamba-yolo/8.19-experiments/`。

### R00：严格公平控制

```text
Original SimpleStem
P3/P4 CrackMergeDirectional
P5 original VisionClueMerge
all Standard VSS
```

R00 与 T00 只有 P3/P4 Unified Block 不同。它是判断 Scan/Memory 是否有效所必需的控制，不属于新结构搜索。

### R01：非负门控、无辅助监督

结构与 T00 相同，但：

- guidance/orientation auxiliary loss 均设为 0；
- write gate 和 scan gate 改为 `[0, gate_max]` 内的 sigmoid 有界参数；
- 方向温度保持 2.0；
- 不改变 Scan 路径、State Update 公式或模块位置。

非负 write gate 保证 `B' = B * (1 + beta * (2g - 1))` 中 `beta >= 0`，不会把裂缝与背景的写入语义反转。

### R02：非负门控加弱正则

R02 与 R01 的唯一差异为：

```yaml
gate_regularization_weight: 0.01
```

训练损失增加 Unified Block 有效 write/scan gate 平方的均值，用于抑制后期过强传播。它不监督 guidance 内容，也不引入新预测头。

## 4. 向后兼容性

`nonnegative_gates` 默认为 `False`，`gate_regularization_weight` 默认为 0。因此 8.17 以及更早 YAML 的数学行为不变。只有 R01/R02 显式启用新约束。

## 5. 训练顺序

第一阶段只训练 R00 seed0：

```bash
python batch_train.py --data ../crack-seg/crack-seg.yaml --phase 19C --seeds 0 --continue-on-error
```

第二阶段训练 R01/R02 seed0：

```bash
python batch_train.py --data ../crack-seg/crack-seg.yaml --phase 19G --seeds 0 --continue-on-error
```

不要根据单 seed 宣布改进。seed0 完成后，选择 R00、R01、R02 中需要正式比较的候选补 seed1/2：

```bash
python batch_train.py --data ../crack-seg/crack-seg.yaml --experiments R00 R01 R02 --seeds 1 2 --continue-on-error
```

## 6. 判定规则

主判据使用 `best_mask.pt`：

1. Mask mAP50-95；
2. Mask mAP75，用于判断精细边界是否恢复；
3. Mask mAP50 和 Recall；
4. mIoU 与 clDice，只作为覆盖和拓扑补充；
5. 三 seed 均值、标准差与逐 seed 方向一致性。

判断逻辑：

- 若 R00 优于 T00：现有 Unified Block 是主要负贡献，不能直接 claim Scan/Memory 有效。
- 若 R01 优于 R00：非负、无辅助监督的 Unified Block 获得直接证据。
- 若 R02 优于 R01：后期 gate 过强确实是问题，可以保留弱正则。
- 若 R01/R02 仍不优于 R00：停止继续调门控初值，回到 guidance/方向定义或放弃当前 Unified claim。
