# 8.23 P5 Directional Unified 候选与 Scan/Write 组件消融

## 1. 8.19 的结论

排除未完成的 `R00_crack-seg_seed1`，并将目录名 `R00_crack-seg_seed12` 按 `args.yaml` 识别为真实 seed1 后，三 seed 结果为：

| 方法 | Mask mAP50 | Mask mAP50-95 | Mask mAP75 | mIoU | clDice | Mask fitness |
|---|---:|---:|---:|---:|---:|---:|
| R00 公平控制 | 0.7037 | 0.2426 | 0.0932 | 0.6486 | 0.8596 | 0.2887 |
| R01 非负 Unified | 0.7031 | **0.2446** | 0.0955 | **0.6494** | **0.8601** | **0.2904** |
| R02 门控正则 | 0.7046 | 0.2424 | 0.0958 | 0.6398 | 0.8481 | 0.2886 |

R01 相对严格控制 R00 的 Mask mAP50-95 在三个 seed 上分别提高 `0.00065/0.00065/0.00455`。提升较小，但方向一致，而且标准差从 0.0028 降到 0.0012。非负门控的最终职责也稳定表现为 P3 write-dominant、P4 scan-dominant。

R02 虽然确实降低了门控幅度，却没有改善性能并显著增大波动，因此 8.23 不再搜索 gate regularization 权重。

## 2. 为什么恢复 P5 Directional Merge

R00 与 N04 都使用 Standard VSS，核心差别是 P5 Merge：

```text
R00: P3/P4 Directional Merge + original P5 merge
N04: P3/P4/P5 Directional Merge
```

N04 相对 R00 的三 seed Mask mAP50-95 提升分别为 `0.00483/0.00544/0.00020`，全部为正；均值从 0.2426 提高到 0.2461，mAP75 从 0.0932 提高到 0.1016。因此“P5 不需要方向细节”的假设没有得到支持。

8.23 的主候选只组合目前已有正向证据的两部分：

```text
P3/P4/P5 CrackMergeDirectional
        +
R01 nonnegative Unified Scan/Write
```

## 3. 实验定义

YAML 位于 `ultralytics/cfg/models/mamba-yolo/8.23-experiments/`。

| ID | Unified Write | Unified Scan | 目的 |
|---|---|---|---|
| Q00 | P3、P4 开启 | P3、P4 开启 | 最终完整候选，先验证能否超过 N04 |
| Q01 | P3、P4 开启 | 关闭 | Write-only，测量 state writing 贡献 |
| Q02 | 关闭 | P3、P4 开启 | Scan-only，测量方向传播贡献 |
| Q03 | 仅 P3 开启 | 仅 P4 开启 | 验证 P3 写入、P4 传播的层级职责 |

四组实验都使用：

- Original SimpleStem；
- P3/P4/P5 Directional Merge；
- 同一个三通道 Unified structure head；
- 非负 gate；
- orientation temperature=2.0；
- 不使用 guidance/orientation auxiliary loss；
- 不使用 gate regularization；
- Standard VSS Neck。

Write-only/Scan-only 不替换成旧 `CrackWriteVSSBlock` 或 `OrientationVSSBlock`。被关闭的作用路径通过 Unified 内部开关禁用，共享 head 保持不变，从而把实验差异限制在 state-write 与 scan effect 本身。

## 4. 训练顺序

### 阶段一：只训练 Q00 seed0

```bash
python batch_train.py --data ../crack-seg/crack-seg.yaml --phase 23F --seeds 0 --continue-on-error
```

进入下一阶段的建议条件：Q00 seed0 的 Mask mAP50-95 不低于 N04 seed0 的约 0.250，或至少明确高于 R01 seed0 的 0.246。

### 阶段二：补齐 Q00 三 seed

```bash
python batch_train.py --data ../crack-seg/crack-seg.yaml --experiments Q00 --seeds 1 2 --continue-on-error
```

只有 Q00 三 seed 不弱于 N04，才把 Q00 作为论文主模型。

### 阶段三：正式组件消融

```bash
python batch_train.py --data ../crack-seg/crack-seg.yaml --phase 23A --seeds 0 --continue-on-error
```

根据 seed0 结果选择必要实验补 seed1/2。正式论文至少应保留 N04、Q01、Q02、Q00；Q03 是层级职责增强实验。

## 5. 必须补齐的非负门控对照

R01 相对 T00 同时关闭了辅助监督并改变了 gate 参数化。已有 T01 是 signed-tanh/no-aux，但只有 seed0。无需新 YAML，直接补：

```bash
python batch_train.py --data ../crack-seg/crack-seg.yaml --experiments T01 --seeds 1 2 --continue-on-error
```

然后比较：

```text
T01: signed tanh gate + no auxiliary supervision
R01: nonnegative sigmoid gate + no auxiliary supervision
```

这组结果决定论文能否把稳定性提升归因于“理论一致的非负门控”。

## 6. 判定逻辑

- `Q00 > N04`：Directional Merge 与 Unified Scan/Write 可以形成最终主模型。
- `Q02 > Q01`：提升主要来自方向自适应 Scan。
- `Q01 > Q02`：提升主要来自 crack-aware state writing。
- `Q00 > Q01 且 Q00 > Q02`：Scan 和 Write 存在互补性。
- `Q03 >= Q00`：P3 write、P4 scan 的显式职责分工更合理且更轻。
- `Q00 <= N04`：Unified 仍没有超过简单 Directional Merge，不应强行作为主模型 claim。

主要指标顺序：Mask mAP50-95、Mask mAP75、Mask fitness；Precision/Recall 用于解释变化来源，mIoU/clDice 作为覆盖与拓扑补充。所有正式结论使用 `best_mask.pt` 和 `segmentation_eval_report_best_mask.txt`。

## 7. 暂停的方向

8.23 不继续尝试：辅助监督、门控正则、temperature=1、ClDice training loss、新 Stem、Neck Unified 或更多扫描路径。先完成 Q00 和必要的因果消融，再决定是否需要边界损失。
