# 8.24 Q00 H/V Scan 映射纠正与稳定性实验

## 1. 本轮只解决一个实现问题

Q00 的共享结构头应输出 `crack probability + horizontal/vertical structure logits`，分别控制 State Write 与 H/V Scan Fusion。代码检查发现旧 `oriented_hv` 路径将两个 scan family 投影到了 `[+x, -x]`：

```text
旧实现分数 = [o_x, -o_x]
预期分数   = [o_h,  o_v]
```

因此旧 Q00 的第二个 orientation 通道没有真正参与 H/V 权重计算。它仍能学习一个标量的 H/V 竞争，但不是预期的双通道 family prediction，可能增加随机种子敏感性。

8.24 不增加 Stem、Delta、对角 Scan、辅助损失、Neck Unified 或新损失，只增加一个向后兼容开关：

```text
orientation_family_logits=True
```

旧 YAML 默认保持 `False`，所以 Q00/R01 的旧权重和旧实验语义不会被静默改变。新路径直接使用：

```text
direction_scores = [o_h, o_v]
a = 2 * softmax(temperature * direction_scores)
w = 1 + scan_gate * (a - 1)
```

所有水平/垂直正反向 Scan 仍然执行；该机制是自适应 Scan Fusion，不是稀疏路由。

## 2. 固定架构

所有 8.24 实验保持：

```text
Original SimpleStem
P3/P4/P5 CrackMergeDirectional
P3 Unified stage
P4 last-block Unified
P5 Standard VSS
Standard VSS neck
YOLO11 Segment head
no auxiliary supervision
no gate regularization
nonnegative bounded gates
```

Q00 的 Memory 仍只调制输入矩阵 B：

```text
B' = B * [1 + beta * (2g - 1)]
```

它是 State Write Management，不包含 Delta retention/forgetting 调制。

## 3. YAML 矩阵

目录：`ultralytics/cfg/models/mamba-yolo/8.24-experiments/`

| ID | 唯一变化 | P3 作用 | P4-last 作用 | 目的 |
|---|---|---|---|---|
| U00 | Q00 仅修正 H/V 双通道映射 | Write+Scan | Write+Scan | 主因果实验，与 Q00 三 seed 直接比较 |
| U01 | U00 的 temperature 2.0→1.0 | Write+Scan | Write+Scan | 减弱 H/V 竞争尖锐度 |
| U02 | U00 的 scan max 0.25→0.15 | Write+Scan | Write+Scan | 限制重复方向增强 |

U04 的初值不破坏 baseline-equivalent 初始化：共享结构头为零时，`g=0.5`、H/V 权重相等，所以 Write/Scan 的实际调制仍为零。

## 4. 推荐训练顺序

### 阶段一：U00 三种子

U00 是唯一必须先完成三种子的版本，因为它与旧 Q00 的唯一算法差异是 H/V 映射纠正：

```bash
python batch_train.py --data ../crack-seg/crack-seg.yaml --experiments U00 --seeds 0 1 2 --device 0,1 --epochs 300 --patience 100 --batch-size 16 --workers 128 --save-period 10 --continue-on-error
```

主要比较：

```text
Q00 mean: Mask mAP50=0.6974, mAP50-95=0.2418, AP75=0.0844
Q00 seed2: Mask mAP50=0.7225, mAP50-95=0.2453
N04 mean: Mask mAP50=0.7041, mAP50-95=0.2461, AP75=0.1016
```

纠正有效的首要证据不是单个 seed 超过 0.7225，而是 U00 三种子均值提升且标准差下降。

### 阶段二：超参数和职责 seed0 筛选

```bash
python batch_train.py --data ../crack-seg/crack-seg.yaml --experiments U01 U02 U03 U04 --seeds 0 --device 0,1 --epochs 300 --patience 100 --batch-size 16 --workers 128 --save-period 10 --continue-on-error
```

不要把四个变体自动全部补三种子。只选择 seed0 在 Mask mAP50-95、AP75 或稳定边界指标上明确优于 U00 seed0 的一个候选。

### 阶段三：只补胜者 seed1/2

例如 U03 胜出时：

```bash
python batch_train.py --data ../crack-seg/crack-seg.yaml --experiments U03 --seeds 1 2 --device 0,1 --epochs 300 --patience 100 --batch-size 16 --workers 128 --save-period 10 --continue-on-error
```

## 5. 判定规则

主指标顺序：

1. `best_mask.pt` 的 Mask mAP50-95；
2. Mask AP75；
3. 三种子均值与标准差；
4. Mask mAP50；
5. mIoU 与 clDice；
6. Params、GFLOPs 和统一环境 FPS。

判断逻辑：

- `U00 > Q00` 且方差下降：旧 H/V 映射是主要稳定性问题；
- `U01 > U00`：temperature=2 导致方向竞争过尖；
- `U02 > U00`：Directional Merge 与 Scan 存在幅度重复；
- `U03 > U00`：P3 Write/P4 Scan 的显式职责分离优于全开启；
- `U04 > U00`：历史学得的门控职责是有效初始化先验；
- `U00 <= Q00`：双通道 H/V 表达本身未带来收益，应保留事实而不能为修复强行 claim；
- 所有 U 版本仍低于 N04：完整 Unified 继续作为机制研究，性能主模型仍选 N04。

## 6. 本轮禁止同时改变的变量

为了保持因果归属，本轮不加入：Delta modulation、CrackDetailStem、辅助监督、clDice training loss、diagonal/sparse scan、Unified neck、gate regularization、新数据增强或优化器搜索。

只有当 U00/U03 的多种子结果证明 corrected Unified 有稳定收益后，才进入边界损失或 Delta retention 的下一阶段。
