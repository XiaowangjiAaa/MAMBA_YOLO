# 8.28 Sparse Adaptive Crack-Path Mamba

## 1. Motivation and final design decision

Cracks occupy only a small fraction of a feature map. A horizontal, vertical, diagonal or snake scan still sends mostly background tokens through the state recurrence. Reweighting several fixed scan outputs can select a less harmful direction, but it neither changes the token order according to the current crack nor removes most background tokens from state propagation.

The final method is therefore not another fixed scan-family variant. It is a sparse, image-adaptive crack-path state propagation block:

1. select a small set of likely crack seeds;
2. trace two local paths from every seed according to the predicted tangent and neighbor connectivity;
3. gather the dynamically ordered tokens into short paths;
4. run a bidirectional Mamba selective state scan on every path;
5. scatter overlapping path outputs back to the 2-D feature map;
6. fuse them residually with the complete local YOLO feature.

The block is named `AdaptiveC3k2CrackPath`. YOLO11 remains the detector/segmenter topology; only the backbone P3/P4 C3k2 stages use the proposed C3k2-compatible block.

## 2. Unified structure field

For compact feature `Z`, one depthwise 3x3 plus pointwise head predicts seven maps:

\[
S(Z)=[p, o_x, o_y, c_H, c_V, c_D, c_A].
\]

- `p`: crack-token probability;
- `(o_x,o_y)`: undirected double-angle tangent `(cos 2theta, sin 2theta)`;
- `c_H,c_V,c_D,c_A`: H/V/main-diagonal/anti-diagonal neighbor connectivity.

These outputs have different responsibilities but come from one shared structure field:

| Signal | Token/path selection | Scan order | Retention | Write | Transition |
|---|---:|---:|---:|---:|---:|
| probability `p` | yes | indirectly | yes | yes | indirectly |
| tangent `o` | no | yes | no | no | yes |
| connectivity `c` | no | yes | no | no | yes |

This preserves the unified story without forcing one ambiguous scalar to perform incompatible roles.

## 3. Sparse adaptive curve construction

### 3.1 Seed selection

For feature size `H x W`, the block selects

\[
K=\min(K_{max},\operatorname{round}(r_sHW))
\]

highest-probability seeds. The reference uses `r_s=0.02` and `Kmax=128`. At 640 input this gives about 128 P3 paths and 32 P4 paths.

Top-K indices are discrete. Probability still receives direct mask supervision and live gradients through gathered path probability, route strength, retention and writing. The local YOLO branch remains dense, so an early imperfect seed predictor cannot remove the original feature.

### 3.2 Image-adaptive next-token selection

At each trace step, eight spatial neighbors are evaluated. For current token `i`, candidate `j` receives a score based on:

\[
s_{ij}=p_j\sqrt{c_i^{f(i,j)}c_j^{f(i,j)}}
\,a(o_i,d_{ij})a(o_j,d_{ij})
\,h(d_{ij},d_{prev}),
\]

where `f(i,j)` selects one of four undirected connectivity families, `a` measures tangent alignment and `h` discourages immediate reversal. The best valid neighbor becomes the next token. Tracing is performed in both signs of the undirected tangent and concatenated into one curved path.

The path is not restricted to one global H/V/diagonal order. Consecutive steps may be right, lower-right, down, lower-left and so on, thereby approximating an arbitrary local curve with an 8-connected discrete path.

### 3.3 Branches and junctions

The first efficient implementation uses an ensemble of overlapping short paths rather than one global graph traversal. Multiple nearby seeds can follow different outgoing directions at a junction; their scattered outputs are averaged at shared pixels. This avoids falsely forcing an entire branched crack into one linear sequence and remains batchable without a custom segmented-scan CUDA kernel.

## 4. Path-level Mamba memory

Every gathered path is scanned forward and backward by `CrackPathSelectiveSSM`. It retains the selective state-space equations and CUDA selective-scan operator. Structure signals control memory as follows:

\[
\hat\Delta_t=\Delta_t+\alpha_m(0.5-p_t)+\alpha_c(1-c_{t-1,t}),
\]

\[
\hat B_t=B_t[1+\beta_w(2p_t-1)].
\]

- high `p` decreases the delta logit and preserves crack history;
- low predecessor connectivity increases delta and quickly removes unrelated state;
- high `p` strengthens current crack-token writing;
- every path boundary has zero predecessor confidence, explicitly resetting cross-path memory;
- forward/backward outputs are aligned and averaged.

Thus geometry determines the predecessor, while probability/connectivity determine what is written and whether that predecessor state is retained.

## 5. Efficient C3k2-compatible integration

`AdaptiveC3k2CrackPath` preserves the YOLO11 C3k2/CSP interface and local bottleneck. Only the last internal repeat adds one sparse path branch. A learned 1x1 projection selects a compact state subspace instead of assuming that the first fraction of convolutional channels contains structural information.

Reference construction under YOLO11-n segmentation:

- original baseline: approximately 2.732M parameters;
- P3/P4 CrackPath model: approximately 2.745M parameters;
- increase: approximately 12.6K parameters, about 0.46%;
- reference state ratio: 0.25;
- reference path length: `2 * path_steps + 1 = 9` tokens.

The dense local YOLO branch retains background context. Only the long-range state propagation branch is sparse.

## 6. Supervision

Three small auxiliary terms are available:

\[
L_{structure}=\lambda_pL_p+\lambda_oL_o+\lambda_cL_c.
\]

- `L_p`: BCE plus Dice on max-pool-preserved crack masks;
- `L_c`: four-family neighbor-connectivity BCE plus Dice;
- `L_o`: double-angle tangent derived from local centerline connectivity, with ambiguous junction/interior votes excluded.

The reference uses `lambda_p=0.10`, `lambda_c=0.03`, `lambda_o=0.005`. These losses train path construction; they are not additional inference heads.

## 7. What can be claimed

The implementation is Mamba-based because dynamically gathered paths are processed by a bidirectional selective state-space recurrence using `SelectiveScanCore`. The full network should be described as:

> A YOLO11-based crack segmentation network enhanced by a sparse adaptive Mamba crack-path propagation block.

The precise scan claim is:

> Crack-relevant tokens are sparsely selected and dynamically ordered into local paths according to predicted crack probability, tangent and connectivity, after which selective state propagation is performed along those image-specific paths.

It should not be described as a global optimal graph traversal. The present method is a vectorized ensemble of local adaptive paths, chosen to preserve efficiency and trainability.

## 8. Parameter optimization plan

All Y-series models keep the complete module. No YAML removes probability, tangent, connectivity, path scan, memory retention, write or transition. The purpose is to find a performant operating point, not to repeatedly test whether the module exists.

| ID | Tuned parameter | Value |
|---|---|---:|
| Y00 | complete reference | seed .02, steps 4, confidence .05 |
| Y01 | seed ratio | .01 |
| Y02 | seed ratio | .04 |
| Y03 | path steps | 3 |
| Y04 | path steps | 6 |
| Y05 | continuation confidence | .02 |
| Y06 | continuation confidence | .10 |
| Y07 | connectivity loss | .01 |
| Y08 | connectivity loss | .05 |
| Y09 | tangent loss | 0 |
| Y10 | tangent loss | .01 |
| Y11 | residual route | .05 |
| Y12 | retention strength | .10 |
| Y13 | transition strength | .10 |
| Y14 | write strength | .10 |
| Y15 | Mamba state size | 16 |

Sixteen YAMLs are sufficient for the first round: one reference plus fifteen controlled parameter changes. More YAMLs before observing these results would create an unnecessarily large interaction search. After seed-0 training, combine the best path-geometry, structure-loss and memory settings into two focused candidates, then train only Y00 and the top two combined candidates with seeds 0/1/2.

## 9. Training order and decision rule

1. `28F`: train Y00 first and verify stable path coverage/loss;
2. `28S`: tune sparse budget, path length and continuation threshold;
3. `28L`: tune structure learning on the same complete reference;
4. `28M`: tune route and state-update strength;
5. build at most two combined candidates from the winners;
6. run three seeds only for Y00 and the top two candidates.

Primary ranking metric is saved-checkpoint Mask mAP50. Mask mAP50-95, AP75, Recall, mIoU and clDice are diagnostic constraints. Report results from `best_map50.pt` revalidation, not only the peak row in `results.csv`.

## 2026-08-30 训练稳定性修正

首轮 Y00--Y15 结果不是有效的性能实验：Y00/Y09/Y15 的 `epoch10.pt` 中 SGD
`optimizer.state` 数量均为 0，而正常 X00 同期为 301。训练 loss 有限但 300 epoch 几乎不变，
证明 AMP 因非有限梯度跳过了所有 optimizer step。

根因位于硬路径追踪的反向图。接近零的 FP16 orientation 进入 `atan2` 后产生奇异导数；top-k、
argmax 和阈值路径本身又是离散路由，不适合由检测损失穿过几何选择反传。修正版采用以下策略：

1. 路径索引、方向和连接分数从检测图 detach，structure head 继续由 probability、tangent 和
   connectivity 三个显式辅助损失训练；
2. 超短路径不再调用面向长图像序列的 CUDA scan kernel，改用 FP32 的 Delta/B/C selective
   recurrence，数学状态更新不变；
3. `state_out` 零初始化，使初始前向严格退化为稳定的本地 C3k2 主路径；
4. tangent supervision 改为有界 Smooth-L1 双角向量回归，移除零向量归一化奇异点；
5. trainer 检测非有限 grad norm，连续 8 次跳步就终止训练，防止再次静默浪费 300 epoch；
6. `check_yaml.py` 新增 AMP backward 与全部 state gradient 有限性检查。

修正后独立模块连续 3 个 AMP step 的 gradient 全部有限，GradScaler 保持 65536，SGD 建立 19
个 optimizer state 且 `state_out` 发生真实更新；Y00 GPU AMP backward 以及全部 16 个 YAML
的结构/FP32 backward 检查均通过。旧 8.28 checkpoint 不可续训，因为其 optimizer 从未更新。

重新训练必须使用全新项目目录：
