# 8.31 Y10 Evidence-Driven Crack-Path Fusion Experiments

## 1. Objective

The 8.31 stage does not redesign the module and does not test whether individual components exist. It keeps the full
YOLO11-based crack-path block and uses the saved-checkpoint results from 8.30 to combine only parameter strategies with
positive evidence. Mask mAP50 from a fresh validation of `best_map50.pt` is the primary metric.

## 2. Corrected 8.30 evidence

Training-time CSV peaks and saved-checkpoint metrics must not be mixed. The authoritative values below come from
`segmentation_eval_report_best_map50.txt`.

| Y15 | d_state 8 -> 16 | 0.7084 | +0.0234 | path-state capacity is a bottleneck |
| Y02 | seed ratio 0.02 -> 0.04 | 0.7062 | +0.0212 | broader path coverage helps, with a speed cost |
| Y06 | continuation confidence 0.05 -> 0.10 | 0.7000 | +0.0150 | rejecting weak background transitions helps |
| Y01 | seed ratio 0.02 -> 0.01 | 0.6966 | +0.0116 | sparse coverage also helps but is weaker than 0.04 |
| Y07 | connectivity loss 0.03 -> 0.01 | 0.6930 | +0.0080 | lighter edge supervision may avoid over-constraint |
| Y05 | continuation confidence 0.05 -> 0.02 | 0.6915 | +0.0065 | permissive continuation has only weak evidence |
| Y03 | path steps 4 -> 3 | 0.6893 | +0.0043 | modest accuracy gain and a clear efficiency benefit |
| Y00 | complete reference | 0.6850 | - | reference |

| Y09 | no orientation supervision | 0.6701 | -0.0149 | explicit tangent learning is necessary |

Y10 improves Mask recall from 0.6787 to 0.7149. It primarily improves crack discovery rather than Mask mAP50-95,
which supports the claim that reliable tangent prediction helps paths reach more true crack tokens. Y15 improves state
capacity downstream of path construction. Their roles are complementary:

```text
stronger tangent supervision -> more reliable token ordering
larger d_state              -> more capacity to retain structure along that ordering
```

This makes Y10 + d_state=16 the first fusion to test. Improvements must not be added arithmetically; both changes may
explain overlapping samples.

## 3. FP32 best_map50 checkpoint correction

Y15 reached 0.71319 in the live EMA validation at epoch 114, while the saved checkpoint revalidated at 0.7084. The old
trainer serialized every EMA with `.half()`, and `strip_optimizer` converted the final model to FP16 again. Thin masks
are sensitive to this quantization.

The corrected policy is:

- `last.pt`, periodic `epoch*.pt`, `best.pt` and `best_mask.pt` remain FP16 for storage and resume efficiency;
- `best_map50.pt` stores an FP32 EMA and carries `ema_precision: fp32`;
- `strip_optimizer` preserves FP32 for this checkpoint;
- final tables use the fresh `segmentation_eval_report_best_map50.txt` value.

Z00 reruns the exact Y10 architecture under this policy. It is required as the same-code reference for 8.31; the old
Y10 result remains historical evidence, not the direct control for the new fusion runs.

## 4. Experiment definitions

All models retain probability, double-angle tangent, four connectivity families, dynamic path construction,
bidirectional selective recurrence, Delta retention, edge transition, crack-aware writing, and P3/P4 placement.

| ID | Fusion on Y10 | Purpose | Phase |
|---|---|---|---|
| Z00 | exact Y10 | FP32 checkpoint reference | 31R |
| Z01 | d_state=16 | primary path-quality/state-capacity fusion | 31C |
| Z02 | seed_ratio=0.04 | broader crack coverage | 31P |
| Z03 | path_min_conf=0.10 | suppress weak background continuation | 31P |
| Z04 | path_steps=3 | reduce drift and latency | 31P |
| Z05 | connectivity loss=0.01 | lighter junction/edge constraint | 31P |
| Z06 | d_state=16 + conf=0.10 | larger state only on reliable paths | 31M |
| Z07 | d_state=16 + seed=0.04 | high-capacity, high-coverage candidate | 31M |
| Z08 | d_state=16 + steps=3 | capacity/efficiency candidate | 31M |
| Z09 | d_state=16 + connectivity loss=0.01 | capacity with softer edge supervision | 31M |
| Z10 | d_state=16 + seed=0.04 + conf=0.10 | more starts but strict continuation | 31M |
| Z11 | d_state=16 + steps=3 + conf=0.10 | short, reliable, efficient paths | 31M |

Stronger transition/write are intentionally excluded because their isolated saved-checkpoint results were negative.
Route and memory strength are excluded because their gains were too small relative to single-seed variance. The 4%
seed configurations are quality-focused and must be measured for latency; dynamic gather/scatter cost is not reflected
reliably by conventional GFLOPs.

## 5. Training sequence

1. Validate all YAMLs with `check_yaml.py --aug31 --quick --device cuda:0`.
2. Train Z00 and Z01 first. Do not launch the rest if Z00 does not reproduce Y10 or if optimizer updates are unstable.
3. Train Z02-Z05 to measure each positive strategy specifically on Y10.
4. Train Z06-Z11 only after the first two phases are numerically valid.
5. Rank by fresh saved-checkpoint Mask mAP50; use mAP50-95, Recall, mIoU, clDice and latency as constraints.
6. Repeat only Z00, Z01 and the top two fused candidates with seeds 1 and 2.

The first-round decision thresholds are:

- Z01 must exceed Z00 by at least 0.005 Mask mAP50 to claim useful synergy rather than seed noise;
- a final candidate should target at least 0.72 on seed 0 before multi-seed promotion;
- a quality candidate with seed_ratio=0.04 must report standardized single-GPU latency;
- a candidate that raises mAP50 while materially degrading mAP50-95/clDice requires qualitative inspection.

## 6. Paper narrative

The innovation remains one coupled block, not separate Y10 and Y15 modules:

1. crack structure estimation predicts probability, tangent and connectivity;
2. structure predictions form image-adaptive crack-aligned token paths;
3. path probability and connectivity condition selective state retention, transition and writing;
4. bidirectional Mamba recurrence propagates state along those predicted paths.

Orientation loss and d_state are training/capacity settings for this block. They should be reported as parameter studies,
not claimed as additional architectural innovations.
