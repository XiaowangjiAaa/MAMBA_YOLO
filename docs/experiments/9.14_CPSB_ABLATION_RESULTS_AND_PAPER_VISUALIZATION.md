# 9.14：9.11 消融结果与论文可视化

## 1. 结论先行

截至本次读取，`output_dir/crack-seg-9.11` 有 **23 个 seed=1 实验**，均有完成标记、results.csv 和 best_map50 复评报告。提前停止的实验也属于完成，不要求全部达到 300 epoch。

目前结果不能支持“adaptive scan 必然优于规则扫描”“完整 memory 的每一项都有正贡献”“所有 YOLO family 都提升”。可视化应帮助解释这些真实差异，不能通过挑图替代不支持假设的数值。

主指标仍为 **Mask mAP50**。所有表中百分数来自归档 `segmentation_eval_report_best_map50.txt`，**没有重新运行 checkpoint 验证**。完整四张表和 CSV 峰值核对表见 [tables.md](../results/9.14-crack-seg-9.11/tables.md)，机器可读来源见 [metrics_audit.csv](../results/9.14-crack-seg-9.11/metrics_audit.csv)。不要混用 best.pt、best_mask.pt 或不同 checkpoint 各自最好的指标。

### 先处理两个会影响结论的问题

| 实验 | CSV 峰值 Mask mAP50 | 峰值 epoch | best_map50 归档复评 | 复评减峰值（百分点） |
|---|---:|---:|---:|---:|
| K01 完整模块 | 69.656 | 200 | 69.05 | -0.606 |
| K10 标准 memory | 68.684 | 131 | 69.31 | +0.626 |
| K11 retention | 69.044 | 101 | 68.74 | -0.304 |

这不是简单的小数位四舍五入。**按 CSV 看，K01 比 K10 高 0.972 pp；按复评看，K01 反而低 0.26 pp。** 在统一复评前，memory 胜负只能作为暂定观察。

当前 trainer 已有 FP32 best_map50 保存逻辑，但这不能证明归档实验使用相同代码；验证精度、融合、EMA/checkpoint 对应 epoch、数据内容、图像预处理等都应核查。这里只列可能因素，不宣称已定位原因。本次不修改训练模块和原结果。

当前代码中还可直接确认：`validator.py` 的训练内验证会在 GPU 强制 half；独立验证走 AutoBackend，并涉及融合/精度选项。因此“FP32 格式保存”并不自动保证训练 CSV 与独立复评使用同一数值路径。动态 top-k/argmax/阈值路由可能放大小差异，但是否解释本次偏差仍需同权重实测。

记录的公共训练参数为 640、batch=16、SGD、seed=1、300 epoch 上限、patience=100、AMP、mask_ratio=4。args 中 data 路径有 `/data/yinwu/...`、`/root/...` 两种环境及相对路径写法；所有报告为 200 张、249 实例，**数量相同不等于数据文件相同**。正式论文前需对验证图片和标签生成清单与哈希，在同一环境统一复评。完整训练协议差异见 [protocol_audit.json](../results/9.14-crack-seg-9.11/protocol_audit.json)。`pretrained: true` 配置项本身也不能证明加载了同一预训练权重。

## 2. 内部扫描消融

| ID | 扫描方式 | Mask mAP50 (%) | Mask mAP50-95 (%) |
|---|---|---:|---:|
| K02 | Raster | 69.55 | 23.28 |
| K03 | Cross | 69.36 | 23.25 |
| K04 | Serpentine | 67.95 | 22.42 |
| K05 | Diagonal | 69.65 | 23.00 |
| K06 | Fixed straight | 69.66 | 23.20 |
| K01 | Adaptive crack path | 69.05 | 23.06 |

归档复评中 K06 最高，K05 仅低 0.01 pp；不能声称这一微小差距具有统计意义。K01 不是该口径最优。即使改看训练 CSV，K01=69.656%、K06=69.654%、K05=69.710%，也没有明显的 adaptive 优势。

**设计审计：这组不是严格的“仅排序”消融。** 当前 `_ordered_paths` 对 K02–K05 的有效相邻 token 赋 predecessor=1，只在序列边界失效；adaptive 使用结构得分作为 predecessor，fixed 使用邻居概率，还可能阈值提前停止。predecessor 又进入 transition memory，因此同时改变了路径顺序、实际有效长度及边置信度语义。

论文应称为 **seed-centred sparse scanning strategy comparison**，不能写成 whole-image dense raster/cross，也不能写“只改变排序、其他完全一致”。若后续要隔离排序效应，应先统一 predecessor/停止规则，或在 standard memory 下做对应比较；这是未来补证建议，本次不改变已训练算法。

优先看 K01/K06/K05 的真实路径、ALL-path coverage、GT coverage recall、path GT precision，回答：路径是否确实贴着裂缝？是否只选粗裂缝而漏掉细裂缝？是否因早停让实际传播太短？这些都是待可视化检验的假设，不是已经观察到的事实。

## 3. Memory 消融

| ID | Retention | Transition | Write | Mask mAP50 (%) | clDice (%) |
|---|---|---|---|---:|---:|
| K10 | 否 | 否 | 否 | 69.31 | 85.34 |
| K11 | 是 | 否 | 否 | 68.74 | 85.58 |
| K12 | 是 | 是 | 否 | 69.28 | 84.43 |
| K13 | 是 | 否 | 是 | 68.27 | 84.79 |
| K01 | 是 | 是 | 是 | 69.05 | 85.79 |

复评中完整 memory 的 clDice 比标准 memory 高 0.45 pp、union IoU 高 0.30 pp，但主指标低 0.26 pp。不能用辅助指标替代预先确定的主指标；也不能在上述 checkpoint 偏差未解决时声称完整 memory 无效。

新脚本直接从 `path_ssm` 本次 forward 输入重建：

```text
retention_bias = effective_memory * (0.5 - p)
transition_bias = effective_transition * (1 - predecessor)
write_gain = 1 + effective_write * (2*p - 1)
delta = softplus(projected_dt + dt_bias + retention_bias + transition_bias)
A = -exp(A_logs)
decay = exp(delta*A)
```

导出的 decay 为 **正向路径、通道及 state 维度平均**。同时显示在同一特征、同一 A、同一 dt bias 下去掉两项 delta 门控的 decay，帮助判断门控实际改变了多少。它不是重新训练的无门控模型，也不是完整因果反事实；write_gain 是 B 的乘数，并不等于最终状态写入量（还取决于 delta、B、x）。路径长度和后续读出共同影响实际记忆，不能把这张图称为“真实 memory lifetime”。

白色区域代表没有被访问，不是 decay=0。概率图固定 0–1，门控图使用明确固定范围，超过色标的值保存在 NPZ 中，不会用每张图独立拉伸门控强度。

本轮 neck-only 最高；backbone 内 P2+P3 最高，P4-only 最低。它**不支持“浅层没有显著裂缝信息所以不应使用模块”的笼统判断**，也不支持越多位置替换越好。位置最优与机制最优仍可能交互，不能直接把分别获胜的因素相加，当作已经验证的新最优配置。

K00 原生 YOLO11n 的本轮结果缺失，无法从此表确定相对原生模型的净增益。也不能用以前不同 seed 的最佳结果来填这行。

最推荐比较 backbone 的同级输出层 4/6（P3/P4），再补 neck 的 16/19（输出融合特征）。neck-only 的机制图要选 13/16/19/22 中相应层，否则 backbone 中没有 CPSB，只有普通特征热力图，这是正常情况。

目前只有 v9c 提供明确的正方向观察，v8n 近似持平，v5n 下降。**“接口可迁移”成立不等于“性能普适提升”已被证明。** v9c 是 c 规模，不可与 n 规模横向比较绝对性能后归因为模块。

v9c 的适配器保留宿主 RepNCSPELAN4 后接 CPSB state 分支；它与 YOLO11 内部 bottleneck 的放置方式不同，应在方法/附录明确。26 仍是 compatibility，不是官方原生 YOLO26 的验证结果。

效率需要警惕：v9c 参数从 27.625M 到 28.150M（约 +1.90%），报告 GFLOPs 从 147.56 到 151.59；归档 inference FPS 为 178.7 对 20.5。由于硬件和计时环境未统一，不能把它写成已证实的 8.7 倍减速，但足以要求统一测速。自定义 sparse routing/SSM 算子的 FLOPs 统计可能不完整，参数少不代表低延迟。

## 6. 论文图像应该如何组织

建议正文选以下三类，其他放附录：

1. **效果图**：相同图片的 Input、GT、baseline/各消融的实例 mask+bbox、TP/FP/FN 图、固定 ROI 放大。绿色 TP、红色 FP、蓝色 FN，尤其展示弱裂缝漏检、背景误检、断裂位置。union 误差图不区分实例身份，需同时看实例预测。
2. **机制图**：同一 P3/P4 的 crack probability、实际路径、ALL-path coverage、正向 retention/transition/write/decay。路径只画前 N 条以免遮挡，但统计用所有路径；不把显示子集覆盖率当完整覆盖率。
3. **样本分布图**：全部所选图片的逐图 IoU/clDice 配对差值；每个点是一张图，包括退化样本。最好在完整 val 上运行。其分布反映图像间差异，不是多 seed 不确定性。

特征图额外输出 channel RMS，表示层的响应强度，**不是 Grad-CAM、不是裂缝概率、不能独立证明因果贡献**。每个模型独立训练，幅度/通道不一；因此相对热图用于看空间分布，不做逐通道相减。NPY 保留原始 RMS，CSV 记录 GT 前景与背景均值及比值。热图按各自 1–99 分位显示，不能因一张更红就判断更好。

默认图片由固定 sample_seed=1 无放回抽样，所有模型使用同一批，不根据预测挑最好看的图；单图或 TXT 可以锁定已选样本。论文需交代选择规则并保留失败例。当前缺 K00，先做扫描与 memory 组的机制比较、v9c 成对有无模块比较，**不能把 K10 称为没有 CPSB 的 baseline**（它仍有路径模块，只是 memory 为 standard）。

已有结果图（真实报告/CSV，不是示意数据）：[扫描](../results/9.14-crack-seg-9.11/scanning.png)、[Memory](../results/9.14-crack-seg-9.11/memory.png)、[位置](../results/9.14-crack-seg-9.11/placement.png)、[Family](../results/9.14-crack-seg-9.11/family.png)。同名 PDF 可直接用于排版。曲线未平滑；横轴提前结束是 early stopping，不是缺失 epoch 后补零。

## 7. 新脚本与运行方式

### 汇总与统计图

`summarize_ablation_results.py` 不加载模型，读取归档报告和 CSV，输出四张表、checkpoint 审计、协议差异、逐行来源和报告 SHA256。`--plots` 需要 matplotlib。不会回写 output_dir。

```bash
python summarize_ablation_results.py --runs-dir output_dir/crack-seg-9.11 --seed 1 --plots
```

### 论文可视化

`visualize_ablation_paper.py` 默认加载 checkpoint 内保存的结构，避免今天的 YAML 与旧权重不一致。通用 `--manifest` 也支持 YAML+pt/pth，但要求 state dict **完整严格匹配**，不会悄悄保留随机权重。

```bash
python visualize_ablation_paper.py --experiments K01 K06 K05 --source crack-seg/data.yaml --split val --max-images 6 --device 0 --output-dir paper_visualizations/9.11-scan
```

更多 Windows/Linux 通用的一行命令见 [visualize_commands_9.14.txt](../commands/visualize_commands_9.14.txt)。请确认本机 data.yaml/crack-seg.yaml 的 val 路径正确。每次使用新输出目录，脚本拒绝往非空目录混写。

### 全部实验与全部数据划分

```bash
python visualize_ablation_paper.py --runs-dir output_dir/crack-seg-9.11 --experiments all --source crack-seg/data.yaml --split all --max-images 0 --device 0 --output-dir paper_visualizations/9.11-all
```

`--experiments all` 自动扫描 runs-dir 的直接子目录，使用每个目录的 `weights/best_map50.pt`（可由 `--checkpoint` 修改）。包含所有 seed，不再用 `--seed` 筛选；目录全名作为标签，避免同 ID 不同 seed 覆盖。缺指定权重的目录打印 SKIP，不替换成其他 checkpoint；不要求完成标记，已有指定权重的未完成实验也包含在内。显式 `--experiments K01 K06` 仍按 `--seed` 查找。

`--split all` 指 **同一个 --source 数据集 YAML 中的 train/val/test**，不是自动从不同服务器的训练 args 中寻找所有数据集。未声明/空的划分打印 SKIP；已声明但无法解析/没有图片的划分报错，不会悄悄略过。不同划分不合并计算指标，train 上的结果不能当独立泛化性能。

对于 SUT-Crack 这种“原图目录 + raster mask 目录”，使用 `--gt-dir` 按同名 stem 匹配 GT，并用 `--split external` 单独标记外部数据集。图像与 GT 必须已经空间对齐；脚本不再旋转或 resize GT，缺失、重名或尺寸不一致会立即失败。默认非零像素为裂缝，需要黑色前景/白色背景数据时才加 `--gt-invert`。该 raster GT 支持 union IoU/Dice/clDice 和 TP/FP/FN 图，但不包含实例 ID，不能计算实例拆分/粘连质量。

`--max-images` 对每个划分分别生效，默认每个划分抽取 6 张；`0` 才处理每个划分的全部图片。所有模型使用同一划分的同一批图片。全实验×全图片会输出很多 PNG/PDF/NPZ，建议先用 `--max-images 1`。

新输出布局（单个实验/划分也采用此布局）：

```text
9.11-all/
  run_plan.json
  K01_crack-seg_seed1/
    train/
      manifest.json
      per_image_metrics.csv
      feature_focus.csv
      routing_memory.csv       # 只有存在被选路径模块时生成
      0000_image_name/          # 预测、误差、热力图、路径/门控
    val/
    test/
  K02_crack-seg_seed1/
    train/
    val/
    test/
  comparisons/
    train/                     # 此划分所有实验的汇总 CSV 和配对图
    val/
    test/
```

每个 CSV 包含 model/split 字段。跨模型对比图每页最多 6 个模型，避免 all 模式生成过高的单张图；各模型的独立图片不会被省略。全模型差值图的参考对象是排序后的第一个实验，仅为可视化参考，不表示其为原生 baseline。

manifest 格式（路径相对该 JSON 所在目录；不同 family 可各自指定语义对应层，层数应相同）：

```json
[
  {"label": "baseline", "weights": "../output_dir/crack-seg-9.11/K28_crack-seg_seed1/weights/best_map50.pt"},
  {"label": "cpsb", "weights": "../output_dir/crack-seg-9.11/K29_crack-seg_seed1/weights/best_map50.pt"}
]
```

默认 `--layers auto --mechanism-layers auto`。脚本先对 checkpoint 保存的实际网络做一次 FP32 dry forward，再用观测到的 stride、checkpoint 内的 backbone 边界以及 segmentation head 的真实输入自动确定：backbone P2/P3/P4/P5 与 neck P3/P4/P5。它不会把 YOLO11 的层号硬套到 v5/v8/v9/v12。扫描和 memory 组的比较图使用 backbone 语义层；位置和 family 组使用最终 neck P3/P4/P5。机制图与特征层选择相互独立，自动查找模型中所有真正包含 `path_ssm` 的 CPSB，因此 K26 会导出 neck CPSB，而不是错误地在 backbone 4/6 寻找机制图。

每个模型/划分会写 `layer_plan.json`；每个比较组会写 `comparison_plan.json`，明确记录自动选中的实际层名、语义角色、比较模型与参考模型。需要复现实验或覆盖异常结构时，仍可显式使用 `--layers 4,6` 和 `--mechanism-layers 4,6`；`--mechanism-layers none` 关闭机制导出。显式选择了不含 CPSB 的机制层时脚本会报错，不会静默生成空机制图。

可选增加 `"yaml": "../ultralytics/cfg/models/...yaml"`。自定义 raw state_dict 需要正确类别数的 YAML。只加载可信 checkpoint。

输出内容：

- `manifest.json`：权重/输入图片 SHA256、模型和命令参数、设备、精度、图片选择。注意：它保证本次可视化输入一致，不能追溯证明历史训练数据一致。
- 每图 `comparison.png/pdf`，指定 `--roi 0.2,0.2,0.8,0.8` 时另存相同裁剪的 `comparison_roi`。
- 每模型每图 prediction、error、feature PNG 和原始 RMS NPY；每个被选层中的路径子模块另存 structure PNG/PDF/NPZ。
- `per_image_metrics.csv`：GT 存在时的 class-agnostic union IoU/Dice/precision/recall/clDice。缺 GT 不当负样本；空标签文件才按已标注空图处理，框标签或坏 polygon 拒绝。**这些不是 per-image instance mAP，也不能替代官方数据集 AP。** 这里 clDice 是现有可视化工具的二值 skeleton 版本，与训练 validator 的实现不保证逐位一致。
- `feature_focus.csv`：原始 RMS 的前景/背景响应；`routing_memory.csv`：有效 token 比率、全路径覆盖和门控统计。
- `paired_pixel_metrics.png/pdf`：相对命令中第一个模型的逐图差值，所有被选图片均保留。

推理固定 batch=1、FP32、不融合，预测、特征和路径来自同一次 forward。没有批量打开整个图像列表，不会复现一次打开数千文件的问题。mask 使用仓库 process_mask 在正方形 letterbox 上生成，然后去 padding 并恢复原尺寸；它与其他 retina-mask 或验证预处理可能有差异，因此不应用于解释归档 AP 的小差值。
