# 9.11 CPSB 三层消融与泛化实验方案

## 1. 本轮更正

实验依次回答三个问题，不能再混成一张表：

1. **CPSB 内部机制**：哪种 token scanning 更适合细长曲裂缝；哪种 memory management 有贡献。
2. **CPSB 部署位置**：应放 backbone、neck 还是二者；浅层、深层及具体 stage 有何差异。
3. **CPSB 泛化能力**：内部结构和位置确定后，能否替换不同 YOLO family 的同类 CSP 特征块。

主指标固定为 **Mask mAP50**。Mask mAP50-95、Mask mAP75、Recall、clDice、Params、GFLOPs、FPS 为辅助指标。新实验默认 `seed=1`，数据划分、增强、epoch、patience 与 checkpoint 选择保持一致。

## 2. 公共锚点

`K01` 是冻结的 G01/H01 完整 CPSB：结构头预测 crack probability `p`、orientation `o`、connectivity `c`；从高概率位置选择稀疏 seeds；adaptive scan 根据 `p+o+c` 沿局部裂缝曲线选取下一 token；状态更新含 probability retention、edge transition 和 crack-aware write；替换 backbone P2-P5 的 C3k2 shell，neck 不变。

公共预算固定为 `seed_ratio=0.02`、`max_paths=128`、`path_steps=3`、`d_state=8`。`K00` 是原生 YOLO11n-Seg，用于判断完整模块相对宿主基线是否提升。

## 3. 第一部分：CPSB 内部消融

### 3.1 Scanning method

所有方法共享 seed、最大路径数、最大路径长度、state 容量和 full memory，只改变 token 排序。传统扫描围绕同一 crack seed 截取 `2*path_steps+1` 个 token，而非对整张图做不等成本的 dense scan。

| ID | Scan | 排序定义 | 作用 |
|---|---|---|---|
| K02 | Raster | 行优先序列的 seed-centred 片段 | 普通一维展开基线 |
| K03 | Cross | 行优先和列优先，双向 SSM 形成四方向 | 常见规则二维扫描对照 |
| K04 | Serpentine | 奇偶行反向的蛇形顺序 | 避免 raster 行间长跳跃 |
| K05 | Diagonal | 对角线 zigzag | 斜向局部连续性对照 |
| K06 | Fixed straight | H/V/对角直线并保留置信度停止 | 规则稀疏直线路径 |
| K01 | Adaptive crack path | 由 `p+o+c` 逐步选择 8 邻域 | 提出的曲线自适应扫描 |

论文中应写成 **budget-matched seed-centred raster/cross/... scan**，不能把 K02-K05 称为完整 whole-image dense scan。完整 dense scan 的状态长度、计算和访存不等，只适合额外效率附表。

K02-K05 只在全局序列边界减少 token；K01/K06 还会因置信度阈值提前停止。因此还应记录每层 `valid_token_ratio`，用实际有效 token 和 FPS 解释效率差异。

### 3.2 Memory management

固定 K01 的 adaptive `p+o+c` scan、位置和路径参数，只改变状态更新：

| ID | Delta retention | Edge transition | B/write | 含义 |
|---|---:|---:|---:|---|
| K10 | 否 | 否 | 否 | 标准 selective state update |
| K11 | 是 | 否 | 否 | 仅测试裂缝概率控制记忆长度 |
| K12 | 是 | 是 | 否 | 再测试不可靠前驱连接的遗忘 |
| K13 | 是 | 否 | 是 | 再测试裂缝位置的选择性写入 |
| K01 | 是 | 是 | 是 | 完整耦合 memory management |

Delta 决定保留多久，transition 决定状态能否从扫描前驱传播，B/write 决定当前信息写入多少。只有真实结果支持时才能声称三者互补；如果某分量无增益，应缩减最终机制和 claim。

## 4. 第二部分：位置消融

全组冻结 adaptive scan + full memory 及所有内部超参数。

| ID | CPSB 位置 | 回答的问题 |
|---|---|---|
| K00 | 无 | 原生 YOLO11n 参考 |
| K20 | Backbone P3 | 单一中浅层是否足够 |
| K21 | Backbone P4 | 单一语义层是否足够 |
| K22 | Backbone P3+P4 | 只放中层的常规方案 |
| K23 | Backbone P2+P3 | 浅层细节是否被背景纹理干扰 |
| K24 | Backbone P4+P5 | 深层语义是否损失细裂缝 |
| K01 | Backbone P2+P3+P4+P5 | 当前完整 backbone 放置 |
| K26 | Neck 四个 fusion block | 仅融合后传播是否有效 |
| K27 | Backbone+Neck 全部八处 | 过度替换是否冗余或难优化 |

除 Mask mAP50 外，应计算每增加一个 CPSB 的参数、FPS 与边际收益。若 K22 胜过 K01，最终模型就应收缩到 P3/P4；不能因为 K01 设计“更完整”而保留它。

## 5. 第三部分：YOLO family 泛化

每个 family 必须成对、n scale、相同数据和 seed：

| Pair | Baseline | CPSB 兼容 shell | 替换范围 |
|---|---|---|---|
| K28/K29 | YOLOv9c-Seg | RepNCSPELAN4 | backbone RepNCSPELAN4 |
| K30/K31 | YOLOv5n-Seg | C3 | backbone C3 |
| K32/K33 | YOLOv8n-Seg | C2f | backbone C2f |
| K34/K35 | YOLO11n-Seg | C3k2 | backbone C3k2 |
| K38/K39 | YOLO12n-Seg | C3k2 + A2C2f | backbone C3k2/A2C2f |
| K36/K37 | YOLO26n compatibility | C3k2 | compatibility backbone |

K34/K35 与 K00/K01 相同，直接复用结果。K28/K29 使用仓库原生 YOLOv9c-Seg；K38/K39 将官方 YOLO12 的 Area Attention、A2C2f 和 YOLO12n-Seg 拓扑回移到当前 fork。YOLO12 官方目前提供 segmentation YAML、但不提供 segmentation 预训练权重，因此这对实验必须都从头训练。当前仓库不是原生 YOLO26，K36/K37 只能称 **YOLO26-style compatibility study**；正式 YOLO26 claim 必须在官方实现中重做。

泛化表的核心是每对的 `Delta Mask mAP50 = CPSB - baseline`。至少两个独立 family 得到一致正增益，才适合声称跨 YOLO 架构可迁移。

## 6. 执行顺序和停止规则

1. `check_yaml.py --sep11` 检查构建、forward、loss、AMP 与梯度。
2. 训练 K01-K06。adaptive scan 不领先时，先修 scan，不进入 family 扩展。
3. 训练 K10-K13，与 K01 组成五行 memory 表。
4. 训练 K00/K01/K20-K24/K26/K27，据此冻结位置。
5. 最后训练 K28-K33 与 K38/K39；K34/K35 复用，K36/K37 可选。

先统一用 seed=1。最终候选和 baseline 确定后才补 seed=0/2 并报告 mean±std。差异小于约 0.3 个百分点时优先视为需要多 seed 验证，而不是确定性提升。

文件位置：新 YAML 在 `ultralytics/cfg/models/11/9.11-experiments/`，命令在 `docs/commands/train_commands_9.11.txt`，结果输出到 `output_dir/crack-seg-9.11/`。
