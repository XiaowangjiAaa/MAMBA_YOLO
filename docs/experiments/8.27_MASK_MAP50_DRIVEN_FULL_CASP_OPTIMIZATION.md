# 8.27 Mask-mAP50-driven Full-CASP Optimization

## 1. Research decision

The primary metric for this crack instance-segmentation project is now fixed as:

1. **Mask mAP50**: model selection, early stopping, experiment ranking and seed comparison.
2. Mask mAP50-95 and Mask mAP75: stricter localization diagnostics.
3. mIoU and clDice: union coverage and topology diagnostics.
4. Precision and Recall: explanation of false-positive/false-negative trade-offs.
5. Params and GFLOPs: efficiency constraints. FPS is reported only under a controlled benchmark.

The 8.27 stage no longer spends the main training budget deleting transition, write or directional propagation. The complete CASP mechanism is fixed. Experiments optimize its learning dynamics, control strength and state capacity.

## 2. Why 8.26 checkpoint selection was misaligned

`best_mask.pt` is selected by:

\[
F_{mask}=0.1\,AP^{mask}_{50}+0.9\,AP^{mask}_{50:95}.
\]

It does not necessarily preserve the epoch with the best Mask mAP50. For example, W00 seed0 reached Mask mAP50 0.70034 at epoch 145, while its best-mask-fitness epoch was 172 and recorded only 0.67384 Mask mAP50.

Starting from 8.27 every segmentation run saves four semantic checkpoints:

- `best_map50.pt`: maximum `metrics/mAP50(M)`; primary paper checkpoint.
- `best_mask.pt`: legacy mask-fitness checkpoint for comparison.
- `best.pt`: original Ultralytics box+mask fitness checkpoint.
- `last.pt`: final/resume checkpoint.

Segmentation early stopping now also follows Mask mAP50. Final evaluation produces `segmentation_eval_report_best_map50.txt` automatically.

Old checkpoints remain loadable: missing `best_mask_map50` metadata is treated as `None` when resuming.

## 3. Fixed complete CASP method

CASP is deployed only at the YOLO11 backbone P3 and P4 C3k2 stages. Local C3k2 processing is retained; only the final internal repeat adds a partial-channel state branch.

```text
Input feature X
  -> local C3k/C3k2 extraction
  -> partial-channel state projection
  -> lightweight structure predictor
       -> crack probability p
       -> horizontal/vertical family scores o
  -> shared crack-edge confidence E
       -> directional scan-output fusion
       -> transition/delta modulation
       -> B/write modulation
  -> bounded residual route
  -> CSP concatenation and 1x1 fusion
```

All X01-X14 experiments keep transition, write and directional fusion enabled. They are parameter studies of one complete method, not component-removal experiments.

## 4. Evidence from trained 8.26 weights

The trained W01/W07 checkpoints revealed that the old structure head had barely learned:

| Checkpoint | route | transition | write | fusion | structure-head weight norm |
|---|---:|---:|---:|---:|---:|
| W01 seed0 P3 | 0.0380 | 0.0967 | 0.0722 | 0.0967 | 0.00166 |
| W01 seed0 P4 | 0.0372 | 0.0967 | 0.0722 | 0.0967 | 0.00095 |
| W07 seed0 P3 | 0.0582 | 0.1193 | 0.0813 | disabled | 0.00258 |
| W07 seed0 P4 | 0.0573 | 0.1193 | 0.0813 | disabled | 0.00102 |

The probability bias remained near zero, so `p` stayed near 0.5. The two orientation biases remained approximately opposite values of only 1e-5, so H/V probabilities stayed near 0.5. Equal transition/fusion values across stages strongly indicate that raw scalar logits were moving mainly because optimizer weight decay pulled them toward zero.

Consequently, 8.26 often behaved like a weak generic SSM residual rather than a genuinely crack-conditioned state propagator. Parameter optimization is meaningful only after repairing this learnability problem.

## 5. 8.27 implementation corrections

### 5.1 Local structure predictor

The old predictor was a zero-initialized 1x1 convolution. It had no explicit local operator for orientation estimation. The 8.27 predictor is:

```text
depthwise 3x3 convolution
-> GELU
-> pointwise 1x1 projection to [p, H, V]
```

The output projection uses a small random standard deviation of 0.01. This retains near-neutral behavior while breaking exact H/V symmetry. The depthwise design adds little computation.

### 5.2 Scalar controls excluded from weight decay

The following raw logits now use zero weight decay:

- residual `route_raw`;
- transition gate;
- write gate;
- directional fusion gate.

Their changes should therefore be caused by the task gradient, not by regularization moving a negative logit toward zero.

### 5.3 Thin-crack-preserving probability supervision

Nearest-neighbor reduction can erase one-pixel cracks at P3/P4. Guidance targets now use adaptive max pooling when reducing resolution. If any foreground crack pixel falls inside a low-resolution cell, that cell remains positive.

Probability supervision is BCE plus Dice:

\[
L_p=L_{BCE}+\lambda_D L_{Dice}.
\]

The overall coefficient `guidance_loss_weight` is deliberately small so the auxiliary head guides state propagation without replacing the instance-segmentation objective.

### 5.4 Correct H/V family supervision

The 8.26 family head predicts H/V logits, while the old optional orientation loss expected a double-angle vector. This semantic mismatch is corrected. Sobel mask gradients provide the local normal; a strong vertical mask gradient corresponds to a horizontal crack tangent and vice versa. X05/X06 test only small weights because derived direction targets are noisy near junctions.

### 5.5 Robust probability-orientation coupling

The old edge multiplied probability and direction completely:

\[
E=P_{pair}O_{pair}.
\]

An incorrect or uncertain direction could suppress a high-confidence crack. The full module now exposes `direction_mix`:

\[
E=P_{pair}\left[(1-\rho)+\rho O_{pair}\right],\qquad 0\leq\rho\leq1.
\]

- `rho=0`: probability-only base edge;
- `rho=1`: original hard product;
- intermediate values: orientation refines but cannot completely veto crack probability.

The reference uses `rho=0.5`.

## 8. Execution policy

Do not train all 15 configurations blindly.

1. Run X00 and X01 with seed0.
2. If X01 is competitive, run X02-X04 and retain the best guidance value.
3. Copy the winning guidance value into the next-round candidate before interpreting X05-X10. The provided YAMLs use X01 as a controlled reference; later refinement may generate a second focused round.
4. Run capacity experiments only after learning/control parameters are selected.
5. Retrain X00 and the final top two CASP candidates with seeds 0, 1 and 2.

Primary ranking uses `segmentation_eval_report_best_map50.txt`. A candidate advances when its seed0 Mask mAP50 improves or remains within 0.2 percentage points while providing a clear efficiency/stability benefit. Final claims require mean and sample standard deviation over three seeds.

## 9. Required diagnostics

For each retained model record:

- best Map50 epoch and `best_map50.pt` report;
- final learned route/transition/write/fusion values for P3 and P4;
- mean/std of predicted crack probability;
- H/V entropy and direction-map visualization;
- Params and GFLOPs;
- Mask mAP50, then Mask mAP50-95, Recall, Precision, mIoU and clDice.

A higher Mask mAP50 is not enough to claim crack-aware behavior if `p` and H/V remain constant. The heatmaps and learned controls must demonstrate that the intended mechanism was actually optimized.

## 10. Claim boundary

If successful, the method can be described as an efficient drop-in C3k2 replacement for YOLO11 in which one shared crack-edge field jointly conditions directional state propagation, memory retention and state writing. Current H/V scan families are structure-conditioned fixed families; they should not be described as deformable scanning exactly along an arbitrary continuous crack curve.
