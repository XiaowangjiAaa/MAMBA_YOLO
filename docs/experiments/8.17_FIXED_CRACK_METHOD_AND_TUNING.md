# 8.17 固定 Crack-Aware 方法与调参实验

## 1. 本阶段的原则

从 8.17 开始不再通过随意替换 Stem、Merge、VSS 层数或 Neck 模块寻找结果。先固定创新结构，只调节辅助监督、门控初值和方向温度。这样不同实验共享相同参数量和计算图，性能差异才可以归因到优化设置，而不是另一个新模块。

## 2. 固定的最终结构

固定 Backbone 为：

```text
Original SimpleStem
  -> P2 Standard VSS
  -> CrackMergeDirectional (生成 P3)
  -> P3 UnifiedCrackAwareVSSBlock，write-dominant
  -> CrackMergeDirectional (生成 P4)
  -> P4 Standard VSS ... + 最后一个 UnifiedCrackAwareVSSBlock，scan-dominant
  -> Original VisionClueMerge (生成 P5)
  -> P5 Standard VSS
```

Neck 全部保留 Standard VSS。统一模块不铺满所有层：P3 负责在仍有足够空间细节时进行裂缝概率门控写入；P4 最后一层在获得更稳定语义后进行方向自适应传播；P2 避免用不可靠的浅层 guidance 干扰状态，P5 和 Neck 避免过度门控和重复传播。

`UnifiedCrackAwareVSSBlock` 共享一个结构预测头，同时输出裂缝概率和局部方向。它包含两个受限残差门：

- Memory/write：`B' = B * (1 + beta * (2g - 1))`，控制疑似裂缝信息写入 state 的强度。
- Scan：在原始 Cross Scan 与内容自适应 H/V 传播之间进行有界融合，控制 state 沿哪个方向传播。

P3 初始化为 write 较强、scan 较弱；P4-last 初始化为 scan 较强、write 较弱。门控仍可学习，但最大幅度限制为 0.25，避免训练初期破坏原始 Mamba 表征。

## 3. `best.pt` 问题的修正

旧版 `SegmentMetrics.fitness` 同时包含 Box 和 Mask 指标，因此 `best.pt` 可能选中检测框较好、裂缝掩膜却不是最好的 epoch。现在每次分割训练会保存三类权重：

- `best.pt`：保留原始 Box + Mask 综合 fitness，保证与旧实验兼容。
- `best_mask.pt`：按 `0.1 * Mask mAP50 + 0.9 * Mask mAP50-95` 独立选择，是裂缝分割实验的主权重。
- `last.pt`：最后一个 epoch。

分割任务的 early stopping 也跟随 mask fitness；检测等其他任务仍使用原始 fitness。旧 checkpoint 不含 `best_mask_fitness` 时仍可正常恢复训练。
`results.csv` 会保留 `metrics/mask_fitness` 列，因而可以直接核对 `best_mask.pt` 对应 epoch。

正式报告应优先验证 `best_mask.pt`，不要再仅根据 `best.pt` 判断模块有效性。

## 4. 新增裂缝结构指标

验证阶段在原有 Box AP 和 Mask instance AP 外增加：

- `metrics/mIoU(M)`：每张图把所有 GT 裂缝实例合并为前景，把置信度不低于 `crack_metric_conf` 的预测实例合并为前景，再计算 foreground IoU，最后对图像宏平均。
- `metrics/clDice(M)`：对上述二值前景进行形态学骨架化，计算拓扑 precision 与 sensitivity 的调和平均，衡量裂缝中心线连续性。

默认 `crack_metric_conf=0.25`、`cldice_iters=20`。它们是验证参数，不参与反向传播。mIoU/clDice 衡量前景覆盖和拓扑连续性，但不能代替实例 AP，也不能判断不同裂缝实例是否被错误合并。因此主结果同时报告 Mask mAP50-95、Mask mAP50、mIoU 和 clDice。

## 5. 8.17 调参矩阵

所有 YAML 位于 `ultralytics/cfg/models/mamba-yolo/8.17-tuning/`，结构和参数量完全一致。

| ID | 唯一调节项 | 目的 |
|---|---|---|
| T00 | 中等辅助监督；P3 write=0.05/scan=0.01，P4 相反 | 固定方法默认设置 |
| T01 | guidance/orientation 辅助监督均为 0 | 判断辅助监督是否反而约束主任务 |
| T02 | 辅助监督提高到 0.01/0.005 | 判断 guidance 学习不足还是监督过强 |
| T03 | 门控初值减弱到 P3 0.02/0.005，P4 相反 | 降低早期扰动 |
| T04 | 门控初值增强到 P3 0.10/0.02，P4 相反 | 判断当前作用强度是否不足 |
| T05 | orientation temperature 从 2.0 降到 1.0 | 减少方向分布过早变尖锐 |

先运行 17A（T00–T02），确定辅助监督；再运行 17G（T03–T05），确定门控强度和温度。不要同时根据单 seed 增加新模块。选出候选后固定 YAML，再补 seed 1、2，并以均值和标准差比较原版。

## 6. 判定顺序

1. 主判据：`best_mask.pt` 的 Mask mAP50-95。
2. 裂缝连续性：clDice。
3. 前景覆盖：mIoU、Mask Recall、Mask mAP50。
4. 代价：Params、GFLOPs、FPS。
5. 至少三个 seed；单次提高不作为创新有效的结论。

如果 AP 提升但 clDice 下降，说明实例形状更容易被命中、连续性却变差；如果 clDice 提升但 AP 下降，说明连接性增强但实例边界或误检需要继续优化。此时应先调现有损失与门控，不改变固定结构。

## 7. 推荐命令

```bash
python check_yaml.py --aug17 --quick --device cuda:0
python batch_train.py --data ../crack-seg/crack-seg.yaml --phase 17A --seeds 0 --continue-on-error
python batch_train.py --data ../crack-seg/crack-seg.yaml --phase 17G --seeds 0 --continue-on-error
python batch_train.py --data ../crack-seg/crack-seg.yaml --experiments T00 --seeds 1 2 --continue-on-error
```

若当前机器没有 selective-scan CUDA 扩展，只做结构预检可使用：

```bash
python check_yaml.py --aug17 --quick --device cpu --imgsz 128 --stub-scan
```

单独验证 mask 最优权重：

```bash
python mbyolo_train.py --task val --weights output_dir/crack-seg-8.17/T00_crack-seg_seed0/weights/best_mask.pt --data ../crack-seg/crack-seg.yaml --device 0 --batch_size 32 --imgsz 640
```
