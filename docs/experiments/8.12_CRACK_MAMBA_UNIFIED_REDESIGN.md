# 8.12 Crack-Mamba 统一重构与消融方案

## 1. 这次重构解决什么问题

此前方案直接复用 Mamba-YOLO 的 `SimpleStem`、`VisionClueMerge` 和普通 `VSSBlock`，仅在少数阶段分别替换为 `OrientationVSSBlock` 或 `CrackWriteVSSBlock`。因此它更准确的表述是“基于 Mamba-YOLO 的局部增强”，还不能严谨地声称整套特征提取器都是我们提出的算法。

8.12 版本把问题拆成三项可以独立验证的设计：

1. Crack Detail Preserving Stem：第一次降采样时保留细线、边缘和局部对比。
2. Crack Merge：阶段间降采样时减少细裂缝消失，并显式保留方向差异。
3. Unified Crack-Aware VSS Block：同一个结构预测头同时控制扫描方向和状态写入，不再把方向传播与 memory management 写成两个互不相干的 block。

注意：这仍然以 Mamba-YOLO/SS2D 为状态空间基座。论文中可 claim “a crack-specific Mamba-YOLO feature extractor”或“a unified crack-aware state-space block”，不能在没有 YOLO/C3k2 替换实验时 claim 为与 Mamba-YOLO 无关的通用 YOLO block。

## 2. Crack Detail Preserving Stem

### 2.1 Lite 版本

`CrackDetailStemLite` 的组织为：

```text
RGB
 └─ 3x3 stride-2 projection
     ├─ depthwise 3x3 local branch
     ├─ high-pass branch: x - AvgPool(x)
     └─ lightweight channel gate
          ↓ fuse
       PixelUnshuffle(2) + 1x1 projection → P2/4
```

关键点：第二次降采样采用 pixel-unshuffle，而不是再用 stride-2 卷积直接覆盖像素；高通残差增强窄裂缝相对平滑背景的响应；depthwise 卷积和 1x1 投影控制计算量。

### 2.2 Directional 版本

`CrackDetailStemDirectional` 在局部分支之外构造水平和垂直一阶绝对差分：

```text
F = Conv3x3,s2(RGB)
L = DWConv3x3,s2(F)
Dx = AvgPool2(|F(x,y)-F(x,y-1)|)
Dy = AvgPool2(|F(x,y)-F(x-1,y)|)
Y = Gate(Conv1x1([L, Dx, Dy]))
```

它比 Lite 版更直接地引入裂缝方向先验，但也可能放大纹理和阴影边缘，因此必须与 Lite 版分别消融，不能预设 Directional 一定更好。

## 3. Crack Merge

### 3.1 Lite 版本

`CrackMergeLite` 保留原 `VisionClueMerge` 的四相位 space-to-depth 主路，同时增加抗混叠局部残差：

```text
Y = Project(PixelUnshuffle2(X)) + Gate(LocalDepthwise(AvgPool2(X)))
```

主路保留四个子像素相位，残差路补充连续局部上下文。它检验“阶段间信息损失”本身是否是性能瓶颈。

### 3.2 Directional 版本

`CrackMergeDirectional` 由四相位特征额外计算左右、上下相位差，并经过轻量门控残差写回。它检验显式方向对比是否比单纯细节保留更适合裂缝。

## 4. Unified Crack-Aware VSS Block

### 4.1 为什么合并 Orientation 与 CrackWrite

旧设计中：

- `OrientationVSSBlock` 只控制四路 scan 输出的融合权重，即“沿哪个方向传播”；
- `CrackWriteVSSBlock` 只调制 selective state update 的 B，即“当前位置写入多少”。

二者功能不同，早期拆开有利于单因素实验，但最终算法继续保留两个命名会让方法看起来像模块拼接。统一版本使用一个共享结构头：

```text
[p, ox, oy] = StructureHead(X)
```

其中 `p` 是裂缝概率，`(ox, oy)` 是无向局部朝向。共享语义让 scan 与 write 都由同一份 crack structure 表征驱动：

```text
direction weights = 1 + gamma_s (w(ox, oy) - 1)
B' = B * (1 + gamma_w (2p - 1))
```

`gamma_s` 和 `gamma_w` 在每个 block 内独立学习，因此所有阶段都使用同一种创新 block，但网络仍能自行学出“浅层少改、P3/P4 强改、深层按需改”的 stage-wise behavior。这修正了“只有特定阶段有创新、其他阶段仍是普通 VSSBlock”的结构不一致问题。

### 4.2 稳定初始化

- 结构头权重与偏置为零：初始 `p=0.5`，四路方向权重均匀；
- scan gate 与 write gate 小值初始化为 0.05；
- centered write 使用 `2p-1`，因此 `p=0.5` 时 B 完全不变。
- 构造零初始化结构头时恢复随机数状态，使相同 seed 下后续原版 SS2D 参数仍保持 paired initialization，减少消融中的初始化干扰。

所以新 block 在训练起点近似原 VSS 行为，然后逐层学习结构感知的偏移，避免一开始破坏已有状态动力学。

## 5. 辅助监督的关键更正

旧代码把 `last_guidance` 和 `last_orientation` 保存为 `detach().clone()`。若 loss 从这两个缓存读取预测，辅助 BCE/Dice/方向 loss 就无法把梯度传回 guidance head；配置里的辅助权重虽然存在，实际只能产生一个无梯度数值。

8.12 更正为两套缓存：

- `last_guidance` / `last_orientation`：保留计算图，供训练 loss 使用；
- `visual_guidance` / `visual_orientation`：detach 后仅供热力图和调试使用。

`check_yaml.py` 新增 `aux graph attached` 检查，避免这个错误再次静默出现。

| N01 | Lite | 原版 | 无 | Stem Lite 单因素 |
| N02 | Directional | 原版 | 无 | Stem Directional 单因素 |
| N03 | 原版 | Lite | 无 | Merge Lite 单因素 |
| N04 | 原版 | Directional | 无 | Merge Directional 单因素 |

所有配置位于 `ultralytics/cfg/models/mamba-yolo/8.12-experiments/`。N06–N11 将辅助监督降到 `guidance=0.01`、`orientation=0.005`，因为现在多个 block 都有预测头，若沿用旧的较大权重，总辅助梯度会随 block 数累积并压过主分割任务。

## 7. 推荐训练顺序与判断规则

1. 先以相同 seed 训练 N00、N01、N02；决定 Stem。
2. 再训练 N03、N04、N05；决定 Merge 以及二者组合是否互补。
3. 训练 N06；这是 Unified block 最干净、最重要的验证。
4. 只有 N06 有效时再训练 N07，并比较“Backbone-only”与“all”。
5. 最后按前端胜者选择 N08/N10，再选择相应的 all 版本 N09/N11。

必须同时报告 mask mAP50-95、mIoU、Recall、clDice、Params、GFLOPs 和 FPS，并至少补 3 个 seed。对于细裂缝，优先用 clDice 与 Recall 判断结构连续性，不能只看 box mAP。

如果 N06 优于 N00、而 N07 下降，结论应是统一状态管理适合 backbone 的结构建模，但不适合已经融合多尺度语义的 neck；这不是“模块不能全部替换”的失败，而是有明确机制解释的作用域结论。若 N06 也下降，应先查看 `p`、方向权重、`gamma_s/gamma_w` 的训练曲线和热力图，再考虑限制到 P3/P4，而不是继续堆模块。
