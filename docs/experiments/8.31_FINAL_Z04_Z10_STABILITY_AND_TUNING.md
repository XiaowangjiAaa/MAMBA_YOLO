# 8.31-final：Z04/Z10 稳定性验证与 Z04 定向优化

## 1. 阶段结论

8.31 的 `best_map50.pt` 复评结果表明，Z04 的 Mask mAP50 为 0.7177，Z10 为 0.7154。Z04 同时具有更高
Recall 和较短动态路径，是当前主候选；Z10 的 AP75 最高，是偏高质量定位的第二候选。Z00 不再重复训练，
Z07 因运行代价异常且没有形成有效结果，从本阶段排除。

本阶段不修改创新模块，不再验证“模块有没有用”。实验只解决两个问题：

1. Z04 和 Z10 的单次结果是否能在 seed 0/1/2 上稳定复现；
2. 在保持完整 crack-aligned scanning 与 crack-conditioned memory management 的前提下，Z04 的参数能否进一步提高 Mask mAP50。

Mask mAP50 是唯一主排序指标。Mask mAP50-95、AP75、Recall、mIoU、clDice 和标准化延迟作为约束指标。
最终数值必须来自重新加载 FP32 `best_map50.pt` 的验证报告，不能使用 CSV 瞬时峰值替代。

## 2. 固定不变的算法

所有 F 系列配置仍然是 YOLO11-Seg，且只在 backbone P3/P4 的对应 C3k2 位置使用
`AdaptiveC3k2CrackPath`。完整模块始终保留：

```text
P3/P4 feature
  -> crack probability + double-angle tangent + connectivity prediction
  -> sparse image-adaptive crack path construction
  -> bidirectional selective recurrence along each path
  -> probability-conditioned retention and writing
  -> connectivity-conditioned predecessor transition
  -> sparse scatter and residual fusion into the YOLO feature
```

因此 F02-F11 都是同一个模块的参数优化，不是组件消融，也不会改变论文创新的定义。

## 3. 多随机种子最终候选

| ID | 来源 | 关键配置 | 训练种子 | 目的 |
|---|---|---|---|---|
| F00 | Z04 | seed=0.02, steps=3, conf=0.05, d_state=8 | 0/1/2 | 主候选稳定性与均值 |
| F01 | Z10 | seed=0.04, steps=4, conf=0.10, d_state=16 | 0/1/2 | 高 AP75 候选稳定性与均值 |

F00/F01 在新目录重新训练 seed0 是有意设计。这样三个种子使用完全相同的代码、checkpoint 规则和输出协议，
避免把旧目录的单次结果与新运行混合。最终报告均值、标准差、最差种子和最好种子；不能只引用最大值。

## 4. Z04 参数优化

所有 F02-F11 只跑 seed0。只有超过 F00 seed0 且没有明显损害拓扑/召回的配置，才晋级 seed1/2。

### 4.1 第一优先级：路径几何和路径可靠性

| ID | 相对 Z04 的唯一变化 | 理由 |
|---|---|---|
| F02 | P3/P4 steps 3 -> 2 | 测试五 token 路径能否进一步减少方向漂移和背景污染 |
| F03 | P3 steps=2, P4 steps=3 | P3 分辨率高、局部细节多，可能只需要更短传播；P4 保留语义覆盖 |
| F04 | P3 steps=3, P4 steps=2 | P4 单个 token 对应更大图像区域，缩短 P4 可避免跨越到背景 |
| F05 | path_min_conf 0.05 -> 0.07 | 温和过滤弱连接，不采用已被证明过强的 0.10 |
| F06 | path_min_conf 0.05 -> 0.08 | 确定 0.05 到 0.10 之间是否存在更好的可靠性阈值 |

Z04 证明 7-token 路径优于 9-token 路径，但不能直接推出越短越好。F02-F04 用于寻找 P3/P4 各自合适的
传播尺度。F05/F06 只收紧路径边界，不改变路径起点和状态容量。

### 4.2 第二优先级：覆盖预算与结构学习

| ID | 相对 Z04 的唯一变化 | 理由 |
|---|---|---|
| F07 | seed_ratio 0.02 -> 0.01 | 减少同一裂缝附近重复起点，兼顾效率；不再尝试已降低 Precision 的 0.04 |
| F08 | max_paths 128 -> 96 | 保持 seed 密度但限制最坏路径数，测试冗余路径上限 |
| F09 | orientation loss 0.01 -> 0.015 | 略微加强切线学习，避免直接跳到过强监督 |
| F10 | connectivity loss 0.03 -> 0.02 | 在 0.03 和表现不佳的 0.01 之间搜索中间值 |
| F11 | probability guidance loss 0.10 -> 0.05 | 防止概率头被辅助任务过度约束，保留端到端检测目标的主导作用 |

F07/F08 是现有实现内对重复路径问题的低风险参数控制，并不等同于 seed NMS。只有它们显示减少路径预算能够
提高 Precision 或 Mask mAP50 后，才值得进一步实现空间 seed 去重算法。

## 5. 训练与晋级规则

推荐顺序：

1. 先跑 F00/F01 的 seed 0/1/2；
2. 再跑 F02-F06；
3. 第一组没有明确结果时再跑 F07-F11；
4. 对所有完成结果重新验证 FP32 `best_map50.pt`；
5. 仅将相对 F00 seed0 提高至少 0.005 Mask mAP50 的微调候选扩展到 seed1/2；
6. 若提升为 0.002-0.005，只在 Recall、clDice 或延迟同时改善时晋级；小于 0.002 视为单种子噪声。

多种子主结论按以下顺序判断：

1. Mask mAP50 三种子均值；
2. 标准差和最差种子；
3. Mask mAP50-95、AP75、Recall、mIoU、clDice；
4. 同一空闲 GPU、统一 warmup 下的延迟。

F00 是默认论文主候选。F01 只有在三种子 Mask mAP50 均值不低于 F00，或 AP75 优势稳定且 Recall 损失可接受时，
才可能替代 F00。不要因为单个最好种子选择最终模型。
