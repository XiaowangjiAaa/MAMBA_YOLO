# 9.10 分割检测结果可视化与逐图评估

项目根目录新增通用脚本 `visualize_seg_results.py`。它不绑定 G01 或某一个模型结构，可以用于 YOLO11、本文 Crack/Mamba 模型以及其他 Ultralytics 分割 YAML。

## 1. 两种 YAML 的含义

- `--model-yaml`：网络结构 YAML，例如 G01 对应的模型配置。完整 Ultralytics `.pt` 已保存网络结构时可以省略；只有纯 `state_dict` 的 `.pth` 建议必须提供。
- `--source`：输入源。它既可以是单张图、图像文件夹或图像列表 TXT，也可以是数据集 YAML，例如 `crack-seg/crack-seg.yaml` 或 `crack-seg/data.yaml`。
- 当 `--source` 是数据集 YAML 时，使用 `--split train`、`--split val` 或 `--split test` 选择数据，并自动寻找 YOLO `labels` 中的 GT。

## 2. 推荐命令

### 单张图像

```bash
python visualize_seg_results.py \
  --weights output_dir/exp/weights/best_map50.pt \
  --source demo.jpg \
  --output-dir visualization_results/single
```

### 整个图像文件夹

```bash
python visualize_seg_results.py \
  --weights output_dir/exp/weights/best_map50.pt \
  --source path/to/images \
  --recursive \
  --output-dir visualization_results/folder
```

### 数据集 YAML 的验证集（推荐）

```bash
python visualize_seg_results.py \
  --weights output_dir/exp/weights/best_map50.pt \
  --model-yaml ultralytics/cfg/models/11/9.1-experiments/G01-z04-backbone-all-c3k2.yaml \
  --source ../crack-seg/crack-seg.yaml \
  --split val \
  --device 0 \
  --batch 8 \
  --output-dir visualization_results/G01_val \
  --save-json
```

模型 YAML 的实际文件名应替换为本项目中对应 G01/其他实验的配置。若 `best_map50.pt` 是完整 Ultralytics checkpoint，通常不传 `--model-yaml` 更稳妥：

```bash
python visualize_seg_results.py \
  --weights output_dir/exp/weights/best_map50.pt \
  --source ../crack-seg/data.yaml \
  --split test \
  --device 0 \
  --output-dir visualization_results/test
```

## 3. 输出内容

输出目录包括：

- `images/`：默认保存标准 instance segmentation 结果，即原图、半透明实例 mask、bounding box、类别名和置信度。
- `per_image_metrics.csv`：每张图的预测数量、Mask AP50、Mask mAP50-95、pixel IoU、Dice、Precision、Recall、clDice 和推理时间。
- `summary_metrics.csv`：数据集级 Mask mAP、宏平均像素指标、微平均像素指标、平均推理时间等。
- `summary_metrics.json`：仅在指定 `--save-json` 时生成。
- `resolved_images.txt`：本次实际处理的图像清单。脚本通过该清单按 batch 逐步读取大数据集，避免一次打开数千张图片导致 `Too many open files`。

单图或普通文件夹模式没有 GT，因此保存预测可视化和推理信息，但 GT 指标列为空。数据集 YAML 模式才计算 GT 指标。无标签 TXT 的数据集图像按负样本处理。

默认 `--visual-style instance` 与常见 Ultralytics predict 输出一致，裂缝类别使用蓝色 mask、蓝色框以及蓝底白字标签，并以无损 PNG 保存。若需要检查预测相对 GT 的错误区域，可切换：

```bash
python visualize_seg_results.py \
  --weights path/to/best_map50.pt \
  --source crack-seg/data.yaml \
  --split val \
  --visual-style diagnostic \
  --output-dir visualization_results/diagnostic
```

其中绿色表示仅 GT，红色表示仅预测，黄色表示预测与 GT 重合。

## 4. 阈值设计

- `--conf 0.001` 是 AP 计算使用的最低预测置信度。AP 需要完整的置信度排序，不建议直接设成 0.25。
- `--visual-conf 0.25` 用于画图以及 pixel IoU、Dice、Recall、clDice，避免低置信度候选污染可视化和二值指标。
- `--mask-threshold 0.5` 是概率 mask 二值化阈值；正常情况下优先使用 Ultralytics 已映射到原图坐标的 mask polygon。

逐图 AP 适合寻找困难样本和失败案例。`summary_metrics.csv` 中的数据集级 AP 适合在相同脚本参数下横向比较，但它是项目内的轻量实现，可能因后处理和插值细节与 Ultralytics 官方 `model.val()` 有小幅差异。论文主表仍应采用官方验证器结果，逐图 CSV 用于解释和诊断。

## 5. 常用附加参数

```text
--max-images 100      只处理前 100 张，用于快速检查
--no-images           只算指标和 CSV，不保存叠加图
--imgsz 640           推理尺寸
--iou 0.7             NMS IoU 阈值
--alpha 0.42          mask 叠加透明度
--line-width 2        轮廓和检测框线宽
```

脚本依赖项目已有的 `ultralytics`、`torch`、`numpy`、`PyYAML` 和 `opencv-python`。应在训练使用的 `mambayolo` 环境中运行，以保证自定义模块可以被正确导入。
