# 9.4 G01：算法思路、核心创新与实现说明

## 1. G01 的身份与正确 claim

G01 是目前实验中表现最好的完整候选之一，其配置文件为：

```text
ultralytics/cfg/models/11/9.1-experiments/G01-z04-backbone-all-c3k2.yaml
```

G01 的宿主网络是 **YOLO11n-Seg**，不是 Mamba-YOLO。它保留 YOLO11 的普通卷积 stem、SPPF、C2PSA、PAN/FPN neck 和 `v11Segment` head，只将 backbone 的四个 C3k2 特征提取块替换为 `AdaptiveC3k2CrackPath`。

因此适合论文的表述是：

> We propose a crack-aligned selective state propagation block that serves as a drop-in replacement for the backbone CSP feature blocks of YOLO11. A shared structural prior jointly determines sparse curved token ordering and state retention/write, enabling state propagation to follow likely crack structures instead of traversing dense background tokens.

不应写成“本文改进了 Mamba-YOLO”或“复用了 Mamba-YOLO backbone”。G01 只借用了 selective state-space model 的状态更新思想；整体检测与实例分割框架是 YOLO11n。

### 当前实验位置

此前 9.1 汇总中记录的 G01 Mask mAP50 为 0.7079，同环境 YOLO11 对照 G00 为 0.6888，绝对差为 +0.0191。这说明 G01 值得作为当前主模型继续做机制消融，但该数值属于历史 run；9.3 起统一使用 `seed=1` 的新实验必须与同样 `seed=1` 的 H00 基线重新成对比较，不能把不同 seed 或不同训练环境的数值直接混在同一消融表中。

## 2. G01 相对 YOLO11n 改了哪里

YOLO11n 原始 backbone 中四个 C3k2 位于 P2、P3、P4、P5。G01 的替换关系如下：

| Stage | Stride | 原模块 | G01 模块 | G01 参数 |
|---|---:|---|---|---|
| P2 | 4 | C3k2 | AdaptiveC3k2CrackPath | `c3k=False, e=0.25` |
| P3 | 8 | C3k2 | AdaptiveC3k2CrackPath | `c3k=False, e=0.25` |
| P4 | 16 | C3k2 | AdaptiveC3k2CrackPath | `c3k=True, e=0.50` |
| P5 | 32 | C3k2 | AdaptiveC3k2CrackPath | `c3k=True, e=0.50` |

以下部分没有替换：

- 两层普通卷积输入 stem；
- P2/P3/P4/P5 之间的 stride-2 Conv；
- SPPF 与 C2PSA；
- neck 中的四个 C3k2；
- YOLO11 segmentation head。

所以 G01 不是把 YOLO 的 backbone 整体换成另一套 Mamba backbone，而是在原 YOLO11 CSP 框架内部加入任务相关的稀疏状态传播。

## 3. 模块层级

```text
YOLO11n backbone
│
├─ P2 AdaptiveC3k2CrackPath
├─ P3 AdaptiveC3k2CrackPath
├─ P4 AdaptiveC3k2CrackPath
└─ P5 AdaptiveC3k2CrackPath
       │
       ├─ 原 C3k2 split / local bottleneck / concat / fusion
       │
       └─ 最后一个内部 local unit
             │
             └─ SparseCrackPathState
                    ├─ channel compression
                    ├─ structure predictor: p + o(2) + c(4)
                    ├─ sparse seed selection
                    ├─ bidirectional curved path tracing
                    ├─ CrackPathSelectiveSSM
                    ├─ scatter states back to 2-D
                    └─ zero-initialized gated residual
```

一个 `AdaptiveC3k2CrackPath` 无论内部 repeat 数是多少，都只在最后一个内部单元后加入一次状态路由。这样既保留 C3k2 的局部建模能力，也避免每个 bottleneck 都执行路径构造和 SSM，控制参数量与训练时间。

## 4. 裂缝结构预测

输入特征先压缩到原通道数的 25%，再使用 depthwise 3×3 和 pointwise 1×1 预测七个通道：

```text
S = Conv1x1(GELU(DWConv3x3(Norm(Conv1x1(X))))))
```

七个输出为：

```text
p = sigmoid(S[0])
o = tanh(S[1:3])
c = sigmoid(S[3:7])
```

- `p`：当前位置属于裂缝结构的概率；
- `o=(cos 2theta, sin 2theta)`：无向裂缝切线；
- `c`：水平、垂直、主对角线、反对角线四种局部连接置信度。

使用 double-angle orientation 是因为裂缝切线没有箭头，`theta` 与 `theta+pi` 应表示同一方向。实际路径方向通过下式恢复：

```text
theta = 0.5 atan2(o_y, o_x)
```

## 5. Crack-aligned adaptive scanning

### 5.1 稀疏起点

G01 不把整张二维特征图展平成 H×W 的长序列。它只从 `p` 中选择概率最高的稀疏 seed：

```text
N_path = min(128, round(0.02 × H × W))
seeds = TopK(p, N_path)
```

这一步直接减少背景 token 进入状态传播的比例。

### 5.2 局部曲线路径

从每个 seed 同时向前和向后生长。每一步只考察当前 token 的八邻域，而不是在 H、V、主对角线、反对角线四条整图扫描结果之间做 soft weighting。

候选邻居 `j` 的选择分数为：

```text
score(i→j) = p_j
             × connection(i,j)
             × align(o_i, d_ij)
             × align(o_j, d_ij)
             × [0.5 + 0.5 align(d_previous, d_ij)]
```

其中：

- `p_j` 排斥明显背景；
- `connection(i,j)` 要求当前点和候选点都支持相应邻接方向；
- 当前与候选 orientation 约束路径沿裂缝局部切线移动；
- heading consistency 抑制无意义的锯齿跳变。

每步选择分数最大的邻居。当最大分数低于 0.05 或超出边界时，该路径停止。G01 的 `path_steps=3`，向前与向后合并后的最大路径长度为：

```text
L = 3 + 1 + 3 = 7 tokens
```

因此这里实现的是 **基于图像内容、局部方向和连接关系的离散曲线路径排序**。它比固定 cross scan 更贴近裂缝形态，但仍应严谨说明：路径限制在八邻域中，通过 hard top-k 与 argmax 构造，不是任意连续曲线，也不是端到端可微的全局路径规划。

## 6. Scan 与 memory 如何形成闭环

G01 的关键不是“增加一个扫描模块，再增加一个独立 memory gate”，而是让同一结构先验同时控制两者。

扫描首先产生有序序列：

```text
X_path = [x_1, x_2, ..., x_L]
P_path = [p_1, p_2, ..., p_L]
S_path = [s_1, s_2, ..., s_L]
```

其中 `s_t` 是扫描步骤产生的前驱可信度，已经融合概率、方向一致性和连接信息。随后 selective state update 使用相同的 `P_path` 和 `S_path`：

```text
delta_hat_t = delta_t
              + alpha_p (0.5 - p_t)
              + alpha_s (1 - s_t)

B_hat_t = B_t [1 + beta_p (2p_t - 1)]

Delta_t = softplus(delta_hat_t + b_delta)
A_bar_t = exp(Delta_t A)

h_t = A_bar_t h_(t-1) + Delta_t B_hat_t x_t
y_t = C_t h_t + D x_t
```

直观解释：

- 裂缝概率高：`0.5-p_t` 较小或为负，有效 Delta 变小，历史状态衰减更慢；
- 裂缝概率低：有效 Delta 增大，更快遗忘背景状态；
- 前驱可信度低：`1-s_t` 增大，阻止不可靠路径继续携带历史；
- 裂缝概率高：增强 `B_t`，使当前裂缝特征更强地写入 state；
- 裂缝概率低：抑制写入，降低背景污染。

因此完整逻辑是：

```text
结构先验决定“谁与谁相邻”
        ↓
形成裂缝对齐 token sequence
        ↓
同一先验决定“记多久、是否跨前驱传播、写入多少”
```

这就是 G01 最重要的自洽性，也是应放在论文主线中的内容。

## 7. 双向短路径状态传播

每条曲线路径以正向和反向各执行一次 selective recurrence，最后对齐并平均：

```text
Y = 0.5 × (Y_forward + Reverse(Y_backward))
```

裂缝本身没有天然起点和终点，双向状态传播能够减少任意扫描起点带来的方向偏置。

路径长度很短，但有效 batch 为 `batch × number_of_paths`。生产实现使用直接的 FP32 并行 recurrence，而不是针对长图像序列设计的 CUDA selective-scan kernel。这样保留输入相关的 Delta/B/C，同时避免此前短路径、AMP 和硬路由组合产生的非有限反向梯度。

## 8. 稀疏回写与安全初始化

路径状态通过 `scatter_add` 写回原二维坐标。同一位置被多条路径访问时取平均，只在真正被路径覆盖的位置产生状态残差：

```text
X_out = X + gamma × M_path × Conv1x1(ScatterAverage(Y_path))
```

其中 `gamma` 是范围受限的可学习 route gate，初始化为 0.02、最大值为 0.5。输出投影采用全零初始化，因此初始时：

```text
X_out = X
```

这使新模块在训练起点近似原始 C3k2，不会立刻破坏 YOLO11 的局部特征。

## 9. 结构辅助监督

由于 top-k、argmax 和路径索引是离散操作，检测损失无法可靠地穿过路径选择训练结构预测头。G01 使用 segmentation ground truth 构造三项轻量辅助监督：

```text
L_total = L_yolo-seg
          + 0.10 L_probability
          + 0.01 L_tangent
          + 0.03 L_connectivity
```

- `L_probability`：BCE + Dice，监督裂缝概率图；
- `L_tangent`：由局部 mask connectivity 生成 double-angle 切线目标；
- `L_connectivity`：监督 H/V/两种对角线的局部邻接关系。

这些 loss 只在训练期间使用。推理时 guidance 完全由当前 feature 预测，不依赖真实 mask。

## 10. 核心创新点

### 创新一：Crack-aligned sparse token ordering

不是让 Mamba 沿固定 raster/cross/diagonal 序列扫描，也不是只对几个固定方向加权，而是根据当前图像预测的裂缝概率、切线和连接关系生成样本相关的短曲线路径。

### 创新二：Coupled scan–memory management

扫描和记忆共享结构先验。扫描产生的 token 邻接和前驱可信度直接进入 Delta modulation，概率图同时调制 retention 与 B/write，从而建立“沿哪里传播”和“传播过程中保留什么”的因果闭环。

### 创新三：Sparse bidirectional selective state propagation

状态只在少量候选路径上传播，并采用双向短序列 recurrence，避免让稀少裂缝 token 被大面积背景序列淹没，同时保持较短的状态传播长度。

### 创新四：YOLO CSP-compatible replacement

模块保留 C3k2 的 split、local processing、concatenation 和 fusion 接口，只增强最后一个内部单元。它不是替换整个 YOLO 框架，因此可以进一步封装为 C3、C2f、C3k2 兼容版本，用于 YOLO family 迁移实验。

## 11. 与常见方案的区别

| 方法 | token 顺序 | 是否抑制背景 token | memory 是否感知裂缝 | G01 的区别 |
|---|---|---:|---:|---|
| Raster/Cross Scan | 固定 | 否 | 通常否 | G01 构造稀疏曲线路径 |
| Direction-weighted Scan | 固定扫描族后加权 | 部分 | 未必 | G01 改变真实 token 邻接顺序 |
| Crack-guided Delta | 固定 | 否 | 是 | G01 同时改变路径与状态更新 |
| Dense graph routing | 图结构 | 可以 | 可以 | G01 只用八邻域短路径，成本更受控 |

## 14. 论文中需要保持诚实的边界

- 当前路径是八邻域中的离散自适应曲线，而不是无限方向、连续空间的任意曲线。
- hard routing 本身不可微，结构头依赖显式辅助 loss。
- G01 已替换所有 backbone C3k2，但没有替换 neck C3k2；这是一种经实验选择的放置策略，不应宣称模块适合网络中的所有位置。
- G01 是 Mamba-based，因为状态传播采用输入相关 Delta/B/C 与线性 state recurrence；但整体架构不是 Mamba-YOLO。
- 当前最强证据是裂缝任务上的 YOLO11n backbone replacement。跨 YOLO family 的普适性必须由各自 paired baseline 实验支持，不能仅凭接口兼容直接宣称。
