# 9.3 G01 定型、因果消融与 YOLO Family 迁移计划

## 1. 今日结论

从今天开始不再无目的地更换主模块。主模型固定为 G01：以 YOLO11n-Seg 为宿主，只替换 backbone 的四个 C3k2，neck 与分割头保持原样。9.1 同环境实验中，G01 的 Mask mAP50 为 0.7079，YOLO11 对照 G00 为 0.6888，绝对提升 0.0191。后续工作不是继续“找一个新模块”，而是回答三个论文问题：提升来自哪里、为什么必须这样组合、能否迁移到其他 YOLO。

主指标固定为 Mask mAP50。Mask mAP50-95、Mask mAP75、Recall、clDice、参数量、GFLOPs、训练和推理速度作为辅助指标。所有最终结论必须使用 `best_map50.pt` 重新验证，不能直接把 CSV 的瞬时峰值当作 checkpoint 结果。

## 2. 冻结后的主模块

每个宿主 CSP block 仍保留原来的局部分支，只把其最后一个内部单元扩展为 Crack-Path State 路由：

```text
host CSP local feature X
        │
        ├── structure head ──> p, o=(cos2θ,sin2θ), c1..c4
        │                         │
        │                         └── sparse seeds + adaptive curved token ordering
        │                                              │
        └──────────────────────────────────────────────┤
                                                       ▼
                                       bidirectional selective state update
                                                       │
                                           zero-init gated residual
                                                       ▼
                                                     X'
```

结构头预测裂缝概率 `p`、无向切线方向 `o` 与四类邻接连通性 `c`。扫描与记忆不是两个孤立模块：`p/o/c` 先决定哪些 token 被选择、下一个 token 是谁以及前驱是否可信；同一组 `p/c` 随后调制 selective state update。

主模型的状态控制保持 G01 不变：

```text
Delta' = Delta + alpha_p (0.5 - p) + alpha_s (1 - s_prev)
B'     = B [1 + beta_p (2p - 1)]
```

其中 `s_prev` 是由概率、方向与连接联合形成的扫描前驱置信度。裂缝概率高时减小有效 Delta，使历史保留更久；前驱置信度弱时增大 Delta，阻止状态跨断裂或背景传播；高概率 token 获得更强输入写入。路径构建是 hard top-k/argmax，几何分支由显式结构辅助损失训练，状态和残差分支由检测/分割损失训练。短路径 recurrence 固定使用 FP32，避免此前 AMP 下的非有限梯度问题。

## 3. 今日代码接口

`SparseCrackPathState` 新增四个正交控制量，默认值仍等价于 G01：

- `path_mode=adaptive|fixed`：自适应曲线路径或 H/V/两条对角线的直线路径控制。
- `cue_mode=p|po|pc|poc`：路径选择使用哪些结构线索。
- `memory_mode=standard|retention|retention_transition|retention_write|full`：逐步加入 Delta 保留、连接阻断与 B 写入。
- `route_enabled=True|False`：关闭时只保留相同结构辅助头，不把状态残差写回特征，用于排除“额外深监督本身”的贡献。

新增两个宿主外壳：

- `AdaptiveC3CrackPath`：对应 YOLOv5 的 C3。
- `AdaptiveC2fCrackPath`：对应 YOLOv8 的 C2f。
- `AdaptiveC3k2CrackPath`：对应 YOLO11 与 YOLO26-style backbone 的 C3k2。

三者共用完全相同的 `SparseCrackPathState` 与 `CrackPathSelectiveSSM`，仅 CSP 外壳不同。跨家族实验因此检验的是状态路由能否替换不同局部特征块，而不是把 YOLOv5/v8 强行改成 YOLO11。

## 4. 实验矩阵

所有新配置位于 `ultralytics/cfg/models/11/9.3-experiments/`。

| ID | 目的 | Scan | Memory | 训练建议 |
|---|---|---|---|---|
| H00 | YOLO11n 原生基线 | 无 | 无 | seeds 0/1/2 |
| H01 | 冻结 G01 主模型 | adaptive, p+o+c | full | seeds 0/1/2 |
| H02 | 排除结构辅助监督贡献 | 不写回 | 不写回 | seed 0 |
| H03 | 2×2：固定扫描、标准记忆 | fixed | standard | seed 0 |
| H04 | 2×2：自适应扫描、标准记忆 | adaptive | standard | seed 0 |
| H05 | 2×2：固定扫描、裂缝记忆 | fixed | full | seed 0 |
| H06 | 路径线索 p | adaptive p | full | seed 0 |
| H07 | 路径线索 p+o | adaptive p+o | full | seed 0 |
| H08 | 路径线索 p+c | adaptive p+c | full | seed 0 |
| H09 | 只用概率控制 Delta | adaptive p+o+c | retention | seed 0 |
| H10 | Delta 再加入低前驱置信度阻断 | adaptive p+o+c | retention+transition | seed 0 |
| H11 | Delta 保留再加入 B 写入 | adaptive p+o+c | retention+write | seed 0 |

H01 同时是 2×2 的第四格、自适应线索的 `p+o+c` 完整格、记忆消融的 full 格，不重复训练多个内容相同的 YAML。扫描与记忆的交互应按差分中的差分解释：

```text
scan effect under standard memory = H04 - H03
scan effect under aware memory    = H01 - H05
memory effect under fixed scan    = H05 - H03
memory effect under adaptive scan = H01 - H04
interaction = (H01-H05) - (H04-H03)
```

如果 interaction 为正，便有证据支持“沿结构排序使裂缝感知记忆更有效”，而不是把 scan 和 memory 写成两项互不相关的技巧。

放置位置不新增重复 YAML，直接使用已经完成的 9.1 G00-G05：G00 是 P3/P4，G01 是全部 backbone，G02-G04 扩展到 neck，G05 是 stage-adaptive 全替换。现有证据已经支持 backbone-only G01，而 neck 全替换并不稳定；因此主论文采用 G01，不再为同一个问题重复消耗 GPU。

## 5. YOLO Family n-scale 迁移

| Pair | Baseline | Proposed | 替换范围 |
|---|---|---|---|
| YOLOv5n-Seg | H20 | H21 | backbone 4× C3 → C3-compatible CrackPath |
| YOLOv8n-Seg | H22 | H23 | backbone 4× C2f → C2f-compatible CrackPath |
| YOLO11n-Seg | H24（等价 H00） | H25（等价 H01） | backbone 4× C3k2 → CrackPath |
| YOLO26n compatibility | H26 | H27 | backbone 4× C3k2 → CrackPath |

每一对必须在同一代码、数据划分、图像尺寸、增强、优化器、epoch、patience、seed 和 checkpoint 选择规则下训练。先用 seed 0 筛选；只有 proposed 相对同家族 baseline 的 Mask mAP50 提升至少 0.005，才补 seeds 1/2 并报告 mean±std。

### YOLO26 的严谨边界

当前仓库是较旧的 Ultralytics fork，没有官方 YOLO26 所需的 `Segment26`、native end-to-end one-to-one head、DFL-free `reg_max=1`、Progressive Loss/STAL 与 MuSGD 训练链。H26/H27 因而是“官方 YOLO26n backbone 拓扑在当前公共分割头下的 compatibility study”，不能在论文中写成原生 YOLO26n 结果。官方配置和模型说明分别见 [YOLO26 segmentation YAML](https://github.com/ultralytics/ultralytics/blob/main/ultralytics/cfg/models/26/yolo26-seg.yaml) 与 [YOLO26 documentation](https://docs.ultralytics.com/models/yolo26/)。

H26/H27 可以验证 C3k2 宿主接口，但由于该旧 fork 无法复现 YOLO26 的关键训练与 head 变化，而且其可支持的 backbone 与 YOLO11 高度相近，这一对结果只放附录或工程兼容性表。正式宣称 YOLO26 可迁移性前，应将模块移植到官方 2026 Ultralytics 分支，再用原生 Segment26 成对复验。代码和配置绝不能通过把 `v11Segment` 改名为 `Segment26` 来伪装。

## 6. 推荐执行顺序

1. 在训练服务器同步整个代码仓库，先运行 `check_yaml.py --sep3 --quick --device cuda:0`。任何 FAIL 都不要开始批量训练。
2. H00/H01 跑 seeds 0/1/2，先确认 G01 的增益在新代码中可复现。
3. H02-H05 用 seed 0，完成辅助监督控制和 Scan×Memory 2×2。
4. H06-H11 用 seed 0，解释方向/连通线索与三种 memory control 的贡献。
5. H20-H25 先跑 seed 0；每个 family 只对通过阈值的 proposed 补 seeds 1/2。
6. H26/H27 最后运行，并保持 compatibility 标签。
7. 统一从 `best_map50.pt` 做独立验证，记录 Mask mAP50、Mask mAP50-95、Mask mAP75、Recall、clDice、Params、GFLOPs、训练时长与 batch=1 latency。

## 7. 结果判定与文章叙述

主 claim 应限定为：提出一个可嵌入 YOLO CSP 特征块的 Crack-Aligned Selective State Propagation 模块。它通过同一结构先验联合决定稀疏曲线 token ordering 与 state retention/write，使状态主要沿裂缝候选结构传播，并保持原 YOLO neck/head 不变。

以下结果组合才构成完整证据：H01 优于 H00；H01 优于 H02，说明不是辅助监督假象；2×2 中自适应 scan 和 crack-aware memory 至少各自有正贡献，最好存在正交互；H06-H08/H01 显示方向和连通性不是冗余预测；H09-H11/H01 说明 Delta、transition 与 B 各自作用；至少 YOLOv5n、YOLOv8n、YOLO11n 中两组 proposed 在多 seed 下稳定优于其 paired baseline。

如果某一完整家族替换下降，不应删除结果或继续改故事。先检查该家族各 stage 的通道数、重复数和 state 路由开销，再把结论收窄为“适用于 C2f/C3k2 backbone”或只替换 P3/P4。模块的可迁移性是实验结论，不是预先保证。
